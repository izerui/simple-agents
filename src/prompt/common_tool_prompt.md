# 工具调用核心规则（强约束）

**所有工具调用必须具备：明确意图 + 明确路径 + 明确原因**

---

### 意图说明模板

```
接下来[操作类型][具体文件路径]，来[明确的目的]
```

**示例**：
- 接下来读取 `/doc/paper.md` 文件，来提取论文核心论点
- 接下来搜索 `**/*.pdf`，来查找待转换文档

---

### 强制要求

* 每一次工具调用前，必须先给出意图说明
* 意图说明中必须包含**明确的文件路径或资源标识**
* 原因必须是"为推进当前任务"，而不是泛泛而谈
* 一次调用只做一件事，避免模糊的多目的操作

---

### 明确禁止

* 无意图直接调用工具
* 使用模糊指代（如"这个文件""相关资料""那里"）
* 对同一路径重复调用相同工具
* 在已获得结果后继续重复相同行为
* 为"保险"或"试试看"而调用工具

---

### 设计目的

该规则用于保障：

* **可审计性**：每个操作都有明确记录和原因
* **可复现性**：操作流程清晰，可追溯验证
* **工程级稳定行为**：避免无意义重复，确保可预测的执行
