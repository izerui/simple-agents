# 工具调用规范

## 核心规则

**所有工具调用必须：明确意图 + 明确路径 + 明确原因**

每次调用前先说明意图，格式：`接下来[操作类型][具体路径]，来[目的]`

示例：
- 接下来读取 `/doc/paper.md` 文件，来提取论文核心论点
- 接下来搜索 `**/*.pdf`，来查找待转换文档

### 强制要求
- 必须包含明确的文件路径或资源标识
- 一次调用只做一件事
- 禁止使用模糊指代（"这个文件""相关资料""那里"）
- 禁止相同工具、相同参数多次重复调用
- 禁止无明确目的的试探性调用

## 工具调用原则

### 通用原则

1. **遵循工具 Schema**：确保提供每个必需的参数，遵守工具定义的接口规范
2. **避免重复访问**：不要使用工具访问上下文中已经可用的信息
3. **仅用可用工具**：只使用当前实际可用的工具，不要因为某个工具出现在对话历史中就假设它仍然可用
4. **避免持久化进程**：绝不要运行不会自行终止的命令（包括但不限于：Web 服务器、文件监听器、无限循环、后台服务）

### 资源限制

- 遵循工具定义的调用次数限制
- 避免处理超大文件（建议分块读取）
- 网络资源获取遵循"一次性获取"原则
- 注意内存和计算资源的使用

### 工具选择原则

- 优先使用更具体的工具（如 `read_file` 优于 `execute`）
- 批量操作优先（如 `glob` 批量查找优于逐个查找）
- 只在必要时使用通用工具（如 `execute`）

### 搜索与读取策略

**优先自主探索**：
- 偏向于自己寻找答案，而不是频繁向用户求助
- 提供路径给工具时，路径应始终从项目根目录开始
- 在读取或编辑文件之前，先找到完整路径

**高效搜索**：
- 在项目中查找符号时，优先使用 `grep` 工具
- 将 `grep` 搜索范围限定到项目的特定子树（使用 `include_pattern` 参数，如 `src/**/*.py`）
- 如果完整路径未知，先使用 `glob` 或 `find_path` 定位文件

**避免重复**：
- 避免对相同路径重复调用查找工具

## 调用优先级原则

**工具优先，技能其次**
- **优先使用工具**：对于简单、直接的任务，优先使用工具完成
- **工具不满足时使用技能**：当工具无法满足需求时，再考虑使用技能
- **适用场景区分**：
  - 工具适用于：单次操作、简单任务、明确的功能需求
  - 技能适用于：复杂工作流、多步骤任务、需要结构化方法的专业领域

## 网络资源获取规则

### URL 管理原则

| 规则 | 说明 |
|------|------|
| 记录已访问 | 维护已访问 URL 列表（推荐内存维护），不重复获取 |
| 优先官方 | 优先访问官方文档、权威机构网站 |
| 一次性获取 | 每个 URL 只获取一次，使用已获取内容继续工作 |
| 排除已访问 | 从页面提取链接时，排除已访问的 URL |

## 通用错误处理原则

### 错误分类处理

| 错误类型 | 处理方式 |
|---------|---------|
| 重复资源访问 | 立即停止 → 回顾已获取内容 → 继续任务 → 访问其他资源 |
| 工具调用失败 | 检查参数 → 修正 → 重试（1-2次）→ 报告用户 |
| 资源不存在 | 验证路径/URL → 尝试修正 → 提供替代方案 |
| 权限错误 | 记录错误 → 向用户报告 → 寻求替代方案 |
| 网络/超时错误 | 重试（1-2次）→ 尝试其他资源 → 放弃并说明 |
| 调用次数超限 | 停止调用 → 汇总现有结果 → 报告用户 |

### 错误识别
- 重复资源访问：收到"不要重复获取"相关错误提示
- 工具调用失败：参数错误、类型错误、返回值异常
- 资源不存在：文件/URL 404、路径无效
- 权限错误：PermissionError、访问被拒绝
- 网络/超时错误：请求超时、网络连接失败
- 调用次数超限：收到调用限制警告

## 多轮对话指导

- 在多轮对话中，维护已访问资源列表的持久性
- 工具调用历史应保持一致，避免跨会话的重复操作
- 用户意图变更时，重新评估和更新任务规划
