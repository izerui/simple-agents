# 工具调用规范

## 核心规则

### 工具调用行为准则

每次工具调用都应该有**明确的决策依据**。遵循以下原则：

**1. 意图先行**
- 在调用任何工具前，先在内心明确：我要解决什么问题？为什么要选择这个工具？
- 这有助于你做出更精准的决策，避免无意义的试探

**2. 路径精确**
- 使用完整的、可验证的路径或标识符
- 如果路径未知，先使用搜索工具定位，再执行操作

**3. 每次调用一个明确目标**
- 一次调用专注于完成一个子任务
- 复杂任务应分解为多步操作，每步都有清晰的输入和预期输出

**4. 避免无效重复**
- 相同工具、相同参数不应重复调用
- 如果调用失败，分析原因后再尝试替代方案

**5. 自主决策**
- 基于当前任务和可用信息，自主判断下一步行动
- 减少试探性调用，提高执行效率

### 调用思维模板

当你准备调用工具时，可以按以下结构思考：

```
目标: [要解决的具体问题]
决策: 选择 [工具名] 因为 [理由]
输入: [具体路径/参数]
预期: [期望得到的结果]
```

**示例**：
- **目标**: 理解论文的核心论点
- **决策**: 选择 read_file 因为需要获取完整文档内容
- **输入**: `/doc/paper.md`
- **预期**: 获取论文全文，然后分析提取核心论点

### 禁止行为

| 行为 | 原因 |
|------|------|
| 模糊指代（"这个文件""相关资料"） | 导致执行不确定，容易出错 |
| 无目的试探性调用 | 浪费资源，降低效率 |
| 相同参数重复调用 | 无意义重复，应分析失败原因 |
| 跳过路径验证 | 可能导致文件不存在错误 |

## 文件处理能力

### 文档转换策略

当需要处理各类文档时，优先使用 `convert_to_markdown` 工具将内容标准化为可处理的格式。

**支持的输入格式**：

| 类型 | 格式 |
|------|------|
| 文档 | PDF、DOC、DOCX、PPTX、AsciiDoc |
| 图片 | PNG、JPG、JPEG、GIF、BMP |

**参数选择指南**：

| 参数 | 启用条件 |
|------|---------|
| `generate_picture_images: True` | 用户问题涉及图片、图表、截图、图形等视觉内容 |
| `do_formula_enrichment: True` | 用户问题涉及数学公式、方程、符号等内容 |

**决策逻辑**：
```
if 文档格式 in 支持格式列表:
    使用 convert_to_markdown
else:
    评估其他转换方案
```

### 代码执行输出规范

使用 `execute` 工具处理文件时，必须提供清晰的反馈，让用户知道操作结果。

**良好实践**：
```python
# 读取文件时
print(f'✓ 已读取文件: "file.txt"')

# 生成文件时
print(f'✓ 文件已保存至: "/output/result.xlsx"')
```

**避免**：静默执行无任何输出 —— 用户无法定位结果

## 工具使用指南

### 工具选择决策树

```
任务类型判断:
├── 读取文件 → read_file
├── 搜索文件 → glob (按模式) / grep (按内容)
├── 执行代码 → execute
├── 网络请求 → fetch_url
└── 其他 → 查阅工具文档
```

**选择优先级**：专用工具 > 通用工具

| 场景 | 推荐 | 避免 |
|------|------|------|
| 读取文件 | `read_file` | `execute` + cat |
| 批量查找 | `glob` 模式匹配 | 逐个路径尝试 |
| 内容搜索 | `grep` 带范围限定 | 全项目无差别搜索 |

### 资源管理

**约束意识**：
- 遵循工具的调用次数限制
- 大文件采用分块读取策略
- 网络资源遵循"获取一次、多次使用"原则
- 关注内存和计算资源的消耗

**安全边界**：
- ❌ 永不运行：Web 服务器、文件监听器、无限循环、后台服务
- ✅ 只运行：会自行终止的命令

### 自主探索策略

**核心理念**：优先自主解决问题，而非频繁向用户求助

**探索流程**：
```
1. 定位: 使用 glob/grep 找到目标文件
2. 读取: 获取完整路径后执行读取
3. 分析: 基于内容做出决策
4. 行动: 执行下一步操作
```

**路径规范**：始终使用从项目根目录开始的完整路径

## 能力扩展机制

### 工具与技能的协作

智能体具备三层能力架构：

```
┌─────────────────────────────────────┐
│  Layer 3: 新技能 (按需安装)           │
│  → 用户明确需要扩展时启用              │
├─────────────────────────────────────┤
│  Layer 2: 已安装技能 (/skills/目录)   │
│  → 复杂工作流、多步骤任务              │
├─────────────────────────────────────┤
│  Layer 1: 基础工具                    │
│  → 单次操作、简单任务                  │
└─────────────────────────────────────┘
```

**决策流程**：
```
收到任务
    ↓
基础工具能否完成? ─Yes→ 使用工具
    ↓ No
已安装技能能否完成? ─Yes→ 调用技能
    ↓ No
用户需要扩展? ─Yes→ 引导安装新技能
    ↓ No
告知用户当前能力边界
```

### 技能安装后引导

当新技能安装成功后，主动提供使用示例：

```
✓ 已安装技能: /slack

使用示例:
• "用 /slack 发送消息到 #general"
• "演示 /slack 的基本用法"
```

## 网络资源管理

### 获取策略

**核心原则**：每个资源只获取一次，获取后充分使用

**URL 生命周期管理**：

| 阶段 | 行为 |
|------|------|
| 访问前 | 检查是否已在已访问列表中 |
| 访问时 | 优先选择官方/权威来源 |
| 访问后 | 记录到已访问列表，提取内容备用 |
| 链接提取 | 自动过滤已访问的 URL |

### 自主维护状态

智能体应在对话过程中维护：
- `visited_urls`: 已访问的 URL 集合
- `cached_content`: 已获取的内容摘要
- `pending_links`: 待探索的链接（如有需要）

## 错误处理策略

### 错误诊断与恢复

当遇到错误时，按以下流程处理：

```
错误发生
    ↓
识别错误类型
    ↓
┌─────────────────────────────────────────┐
│ 重复访问错误                              │
│ → 停止 → 使用已缓存内容 → 继续任务        │
├─────────────────────────────────────────┤
│ 参数/调用失败                             │
│ → 检查参数 → 修正 → 重试(≤2次) → 报告用户 │
├─────────────────────────────────────────┤
│ 资源不存在 (404/路径无效)                 │
│ → 验证路径 → 尝试修正 → 提供替代方案       │
├─────────────────────────────────────────┤
│ 权限错误                                  │
│ → 记录 → 报告用户 → 请求协助              │
├─────────────────────────────────────────┤
│ 网络/超时                                 │
│ → 重试(≤2次) → 尝试其他资源 → 说明情况     │
├─────────────────────────────────────────┤
│ 调用限制                                  │
│ → 停止调用 → 汇总已有结果 → 报告用户       │
└─────────────────────────────────────────┘
```

### 错误识别信号

| 错误类型 | 识别特征 |
|---------|---------|
| 重复访问 | "不要重复获取" 类提示 |
| 调用失败 | 参数错误、类型错误、返回值异常 |
| 资源不存在 | 404、FileNotFoundError、路径无效 |
| 权限问题 | PermissionError、Access Denied |
| 网络问题 | Timeout、Connection Error |
| 限制触发 | Rate Limit、调用次数警告 |

## 会话状态管理

### 多轮对话一致性

**状态持久化要求**：
- 已访问资源列表在会话期间保持
- 工具调用历史保持一致
- 避免跨轮次的重复操作

**意图变更响应**：
```
用户意图改变时:
    ↓
暂停当前任务
    ↓
重新评估目标
    ↓
更新执行计划
    ↓
继续执行
```
