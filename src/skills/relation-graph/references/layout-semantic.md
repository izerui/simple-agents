# 布局参考

## 定位

它是一套教材式知识建模版式实践：
- AI 负责理解知识语义
- AI 负责判断节点角色、分区与目标坐标
- 脚本只负责校验坐标、处理局部冲突、冻结旧节点、计算连接点、输出稳定结果

## 画布原则

- 画布原点为 `(0, 0)`
- `x` 向右增大，向左减小
- `y` 向下增大，向上减小
- 节点默认使用固定坐标，不做整体自动重排
- 任意两个节点至少保持 `20px` 安全间距

## 区域规则

`graph-data-1774064516149.json` 是当前布局参考的直接风格样例。新建图与增量图都应优先贴近这张图已经体现出来的稳定版式，而不是仅满足抽象分区。

### 1. 主干区

适合放置：
- 根节点
- 一级核心概念
- 主阅读路径上的核心结构节点

建议：
- 根节点与一级主干节点采用“中心偏左主区”
- 主干节点之间留出较大间距，维持明显枢纽感
- 主干区优先承担枢纽连接，不堆叠过多枚举节点
- 主干应保持整体稳定，增量时不为新增外围节点整体重排

### 2. 步骤区

适合放置：
- `data.type=3` 的程序性知识
- 流程、操作步骤、方法链路

建议：
- 优先形成左侧纵向步骤列
- 同一流程保持近似固定 `x` 轴，按顺序递增 `y`
- 左侧或左下侧优先，避免穿越主干阅读路径
- 组内垂直间距建议 `50-80px`
- 若样例中已有步骤列，新增步骤节点优先沿旧列尾插，而不是另起一列

### 3. 枚举区

适合放置：
- 同父节点的并列项
- 同类方式、类型、组成项

建议：
- 同父枚举项优先在主干外缘成组排列
- 可横向排布，也可纵向成组，但同组方向必须统一
- 不要与主干核心节点混排
- 兄弟节点优先尾插，延续既有排列方向
- 若已有同组旧节点，新增节点优先沿该组主方向继续追加

### 4. 案例区

适合放置：
- `data.type=6` 的案例、实例、范例、示例资源

建议：
- 优先分布在外围扇区，如右侧、右下、下方、左下
- 与依附知识点保持清晰挂接
- 避免穿越主干阅读路径
- 多个案例可在外围成组排列
- 冲突时优先向外扩，不要挤回主干中部

### 5. 策略/方法区

适合放置：
- `data.type=5` 的学习策略、分析策略、方法提醒

建议：
- 保持边缘辅助区定位
- 作为补充说明，不进入中心骨架
- 与主节点保持轻量挂接关系
- 增量时优先沿既有边缘辅助区追加，而不是插入主干空白处

## 常见分组规则

### 步骤列
- 同一流程节点优先共用一条纵向轴线
- 顺序从上到下保持一致，除非原图已形成反向链路
- 组内节点宽度可不同，但列的主 `x` 轴应稳定
- 连线方向优先体现流程语义：步骤链优先 `top -> bottom`

### 枚举组
- 同父枚举项按横向或纵向统一排列
- 若已有旧组，新增项优先尾插
- 同组内部间距尽量一致
- 连接方向应兼顾阅读顺序，优先从主干朝向组外侧展开

### 案例外挂
- 案例节点优先挂在知识点外围
- 多个案例可做局部簇状排列
- 避免跨越主干区形成长距离穿插
- 连线连接点优先朝向主干一侧，保持“外围挂接”观感

### 颜色语义
- 核心、先决、结构节点的颜色不只是字段填写，还要与空间层次协同
- 主干核心节点可用更强识别度颜色，并放在主阅读区
- 先决或支撑节点的颜色应与其辅助或前置角色相匹配
- 外围案例与策略节点通常保持边缘辅助定位，颜色不应误导为主干核心

## 间距建议

- 最小安全间距：`20px`
- 主干区水平间距：`120-220px`
- 主干区垂直间距：`80-160px`
- 组内水平间距：`60-120px`
- 组内垂直间距：`50-80px`
- 外围案例区与主干区建议额外预留 `80px+`

## 增量修改规则

- 旧节点默认冻结不动
- 增量请求中，未改旧节点应放入 `preserveNodeIds`
- `preserveNodeIds` 中的节点坐标保持稳定，不参与重排
- `targetNodeIds` 只包含本轮新增节点或允许局部调整的节点
- 未明确修改的旧节点样式应沿用原 JSON；脚本只做必要的规范化补齐
- 新节点必须由 AI 直接给出目标坐标
- 新节点优先插入对应语义区域
- 若目标区域已有同类节点，优先沿既有排列方向尾插或侧插
- 脚本只在明显冲突时做最小位移，不做整体重排
- 冻结节点的既有坐标应保持稳定

## 输入要求

请求 JSON 应用于当前布局脚本：
- `mode`: `create` / `incremental`
- `nodes`: 全量节点，必须直接包含 `x/y`
- `lines`: 全量连线
- `preserveNodeIds`: 增量时冻结的旧节点
- `targetNodeIds`: 增量时本轮新增或需局部调整的节点
- `rootId`: 可选根节点

说明：
- `layout` 字段不是必需字段
- `layoutOptions` 不使用
- `width/height` 可缺省，由脚本按文本估算

## 执行职责

`layout_graph.py` 负责：
- 读取并接收布局请求
- 校验节点和连线引用
- 完成布局处理
- 输出稳定的布局结果

AI 负责：
- 理解知识结构
- 识别节点角色
- 规划区域
- 直接提供符合教材式版式的目标坐标
- 每次生成后都通过 `layout_graph.py` 与 `validate_json.py` 完成落地与校验
