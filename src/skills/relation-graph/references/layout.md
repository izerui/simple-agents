# 布局参考

## 定位

这份文档用于指导 AI 把画布、坐标、节点分区、关系拓扑、阅读顺序作为一个整体来规划。

目标不是“把节点摆开”，而是生成一张：
- 阅读路径清晰
- 主次层级明显
- 分区稳定
- 连线方向自然
- 适合增量扩展

`x/y` 不是随手填写的坐标，而是布局决策的最终结果。

## 使用顺序

生成坐标时按这个顺序思考：

1. 识别语义根和主干
2. 识别步骤链、枚举组、案例、策略
3. 规划画布区域和主阅读方向
4. 再填写 `x/y/width/height`
5. 最后检查连接点与整体可读性

不要边想边散点。先决定骨架，再落坐标。

## 语义根判断

“根节点”优先按语义中心判断，不要只按入度/出度机械判断。

原因：
- 有些图的关系方向是“叶子指向中心概念”
- 有些定义类、属性类关系会让中心节点看起来不是图论上的 root
- 模板图里就存在多个无入边节点，但真正的阅读中心仍然很明确

优先作为语义根的节点通常具备这些特征：
- 主题最总括
- 能统领多个一级分支
- 位于主阅读路径的中心位置
- 不是案例、不是策略、不是局部步骤项

如果用户显式给了 `rootId`，以用户提供内容为准。

## 坐标系

- 画布原点：`(0, 0)`
- `x` 向右增大，向左减小
- `y` 向下增大，向上减小
- 节点左上角由 `x/y` 定位
- 节点中心点为 `x + width / 2`、`y + height / 2`

任何布局判断都必须结合：
- `x`
- `y`
- `width`
- `height`

不要只看中心点。

## 画布与阅读方向

默认采用“中心主干 + 左侧步骤 + 右侧展开 + 外围挂接”的阅读结构。

推荐阅读顺序：
- 先看中心主干
- 再看左侧或下行步骤链
- 再看右侧的枚举/模式/组成
- 最后看外围案例与策略

如果内容天然是流程型任务，可以把“左侧纵向步骤列”提升为更强的视觉主轴，但仍应保留中心主干作为概念锚点。

## 布局计算

布局时要主动计算，而不是凭感觉摆放。

至少同时计算这三类量：
- 间距：节点之间、组之间、主干与外围之间的留白
- 对齐：同组节点是否共享中心线、行基线或列基线
- 边距：节点到所属区域边界、父节点外缘、画布主要阅读走廊的安全距离

布局结果应满足：
- 同一分组内部的间距稳定
- 同一流程或枚举的对齐方式稳定
- 重要节点与区域边界之间保留呼吸感，不要贴边

## 版式骨架

### 主干区

适合放置：
- 语义根节点
- 一级核心概念
- 主阅读路径上的核心结构节点

要求：
- 根节点优先放在中心或中心偏左
- 一级主干围绕根节点建立稳定骨架
- 主干节点之间保持明显留白
- 主干区不要塞入大量案例和局部步骤

布局偏好：
- 主干优先形成 1 条清晰主轴，必要时再扩成 2 到 3 个一级分支
- 主干节点尽量避免上下左右同时大量发散
- 一级分支数量较多时，优先把“流程/步骤”分流到左侧，把“模式/类型/组成”分流到右侧

### 步骤区

适合放置：
- `data.type = 3` 的程序性知识
- 流程、步骤、方法链路、操作顺序

要求：
- 优先形成左侧纵向步骤列
- 同一流程尽量共用稳定 `x`
- 节点顺序按 `y` 从上到下展开
- 不要让步骤链穿越主干区

布局偏好：
- 同一条步骤链尽量使用单列
- 如果步骤过多，优先纵向拉长，不要轻易折返成 Z 字
- 步骤列与主干区之间保留明显走廊，避免连线与主干节点互相穿插

### 枚举区

适合放置：
- 同父节点下的并列项
- 类型、特征、组成、分类、模式、并列方法

要求：
- 同组节点统一横排或统一竖排
- 优先贴父节点外缘成组排列
- 同组方向必须一致
- 不要把同组节点打散到多个区域

布局偏好：
- 右侧优先用于容纳横向或纵向枚举组
- 如果父节点本身已在右侧，枚举组可继续向右或向下展开
- 枚举数量较少时优先横排；数量较多或标签较长时优先竖排
- 多个并列节点需要对齐时，优先对齐中心点而不是只对齐左上角

### 案例区

适合放置：
- `data.type = 6` 的案例、示例、范例、应用实例

要求：
- 优先挂在外围扇区
- 与依附知识点保持清晰挂接
- 位置优先在右侧、右下、下方、左下等外围区域
- 不要把案例塞回主干中部

布局偏好：
- 案例节点默认视为“外挂说明”，不是并列主干
- 如果一个知识点挂多个案例，案例之间应沿同一外缘方向展开
- 案例与主干之间保留额外空白，保证它们看起来像外围补充而非主轴竞争者

### 策略区

适合放置：
- `data.type = 5` 的认知策略、学习建议、方法提醒、使用建议

要求：
- 保持边缘辅助定位
- 不抢主干视觉中心
- 作为补充说明轻量挂接

布局偏好：
- 策略节点优先贴依附节点外缘放置
- 如果案例和策略同时存在，策略应比案例更靠边、更轻

## 区域优先级

默认区域优先级如下：

1. 中心或中心偏左：语义根、一级主干
2. 左侧纵列：步骤链、程序性知识
3. 右侧与右下：枚举组、模式、组成、分类
4. 外围扇区：案例节点
5. 最边缘：策略节点

如果内容与这个模式冲突，以语义可读性优先，但不要无理由打破分区。

## 拓扑规划

布局不仅是节点位置，还包括关系拓扑是否自然。

### 主阅读路径

主阅读路径应满足：
- 层级清楚
- 连线方向稳定
- 尽量短连
- 尽量少跨区

优先顺序：
- 主干到主干
- 主干到步骤/枚举
- 主干到案例/策略外围挂接

布局偏好：
- 主阅读路径上的相邻节点，视觉距离应小于跨分区节点
- 主阅读路径不要被案例或策略节点截断

### 步骤链

步骤链应满足：
- 纵向连续
- 顺序稳定
- 连线方向优先 `bottom -> top`
- 整列视觉上像一条流程链

布局偏好：
- 单条步骤链内尽量不要混入非步骤节点
- 步骤节点高度可略有差异，但列中心应稳定

### 枚举组

枚举组应满足：
- 兄弟节点成组
- 间距一致
- 组内方向一致
- 父节点到子组的展开方向自然

布局偏好：
- 同一枚举组优先共享一个“行基线”或“列基线”
- 如果一个父节点同时有步骤链和枚举组，枚举组不要挤占步骤列

### 外围挂接

案例和策略节点应满足：
- 贴近依附节点
- 挂在主干外侧
- 不穿越主阅读路径
- 连线像“外挂”而不是“并列主干”

## 尺寸与间距

### 尺寸

- `width` 和 `height` 必须直接给出
- 尺寸应与文本长度匹配
- 同组节点尺寸可不完全相同，但整体视觉要稳定
- 文本较长的节点优先增大宽度，其次再增高

### 安全间距

- 任意两个节点最小安全间距：`20px`
- 节点不能重叠
- 连线文本较长时，应额外拉开间距
- 节点与所属区域或容纳边界之间至少保留 `30px` 安全边距

### 推荐间距

- 主干区水平间距：`120-220px`
- 主干区垂直间距：`80-160px`
- 步骤列垂直间距：`45-80px`
- 组内水平间距：`60-120px`
- 组内垂直间距：`50-80px`
- 外围案例区与主干区额外预留：`80px+`
- 策略节点到依附节点的外缘偏移：`80-140px`

主干区留白应明显大于外围区，不要把所有节点均匀铺满画布。

## 坐标生成偏好

### 程序化定位规则

需要程序化判断对齐或落点时，优先用中心点而不是只看左上角：

- 水平中心：`x + (width / 2)`
- 垂直中心：`y + (height / 2)`

适用规则：
- 多个节点横向排布时，优先让它们的垂直中心一致
- 多个节点纵向排布时，优先让它们的水平中心一致
- 同一枚举组或步骤列如需严格对齐，优先匹配中心坐标，再微调左上角坐标
- 父节点带一组子节点时，优先按父节点中心线展开，而不是机械贴齐父节点左边或上边

### 主干落点

主干落点时优先：
- 先放语义根
- 再放一级主干
- 再放二级支撑节点

推荐做法：
- 先给根节点预留中心位置
- 按阅读顺序把一级分支布到左、右、下等主区域
- 只有在内容明显需要时，才把重要节点放到根节点正上方

### 子节点相对父节点的位置

- 右侧：`child.x = parent.x + parent.width + spacing`
- 左侧：`child.x = parent.x - child.width - spacing`
- 下方：`child.y = parent.y + parent.height + spacing`
- 上方：`child.y = parent.y - child.height - spacing`

经验偏好：
- 步骤节点优先放父节点左侧或左下延伸列
- 枚举节点优先放父节点右侧或下侧
- 案例/策略优先放父节点外缘

### 多子节点成组

横向成组时：
- 先算总宽度
- 再以父节点中心为基准左右展开

纵向成组时：
- 先算总高度
- 再以父节点中心为基准上下展开

目的不是绝对对称，而是让同组节点：
- 间距均匀
- 展开方向统一
- 与父节点关系清楚
- 中心线尽量稳定

### 新增节点落点顺序

当一个新节点存在多个可落点区域时，优先级如下：

1. 延续原有分组方向
2. 延续原有步骤列或枚举组的尾部
3. 选择不会切断主阅读路径的位置
4. 选择连线更短的位置
5. 选择更外围的位置，而不是挤占主干

## 连接点选择

优先按相对方位选连接点：

- 目标在右侧：`right -> left`
- 目标在左侧：`left -> right`
- 目标在下方：`bottom -> top`
- 目标在上方：`top -> bottom`

补充规则：
- 步骤链优先上下连接
- 同层横向关系优先左右连接
- 外围挂接的案例/策略节点，连接点优先朝向主干一侧
- 难以判断时可使用 `border`
- 连线方向应自然，不要明显穿过节点主体或破坏主阅读路径
- 如果关系文本显示在线路附近，应优先避免文本压住节点，或落在拥挤交叉区域

## 增量修改

增量时优先保持旧图稳定，不做整图重排。

要求：
- 旧节点尽量保持原坐标
- 新节点沿原有步骤列、枚举组、外围扇区方向追加
- 若原图已经形成稳定分组，新增节点优先尾插
- 不要为了加入一个新节点破坏整张图的骨架

增量优先策略：

1. 保持主干不动
2. 沿既有步骤列尾插
3. 沿既有枚举组侧插或尾插
4. 案例和策略优先向外围扩展

## 常见坏味道

以下情况通常说明布局质量不够好：

- 只因为局部拥挤就把主干节点甩到外围
- 步骤节点横向来回折返
- 同组枚举节点有的横排、有的竖排
- 案例节点落在主干中心区域
- 策略节点比主干节点更靠中心
- 主阅读路径被长跨线切断
- 画布四周很空，但中心过度拥挤

## 模板参考

`references/templete.json` 可作为现有图谱风格示例，用于观察：
- 主干、步骤列、枚举组、案例外挂的大致分区方式
- 常见节点尺寸、纵列间距、外围案例放置方式
- 不同语义类型在画布中的相对位置

它是风格参考，不是结构权威。

冲突处理优先级：
1. `references/schema.json`
2. 用户当前任务的内容与增量约束
3. 本文档
4. `references/templete.json`

## 生成前自检

给出最终坐标前，至少检查：

1. 是否先按语义而不是仅按图论入度找到了根节点
2. 主干是否形成清晰骨架
3. 步骤节点是否形成稳定步骤列
4. 同父枚举是否成组且方向一致
5. 案例和策略是否位于外围
6. 是否有明显重叠、挤压、跨区穿插
7. 连线方向是否顺阅读路径
8. 主阅读路径是否被外围节点打断
9. 整体是否保留了明显留白和层次
