## 一、目标

生成一份适合 LLM 执行的关系图布局规范，核心要求只有四个：

1. 骨架清楚
2. 分区明确
3. 节点不重叠
4. 连线尽量短且少交叉

优先级固定如下：

1. 先保证全局分区清楚
2. 再保证父子关系顺眼
3. 再减少局部交叉
4. 最后再做视觉微调

不要为了某一条边的最优，破坏整张图的结构稳定性。

---

## 二、坐标语义

### 2.1 画布坐标系

画布以视觉中心为原点：

```text
        负Y（上）
         ↑
  负X ←──┼──→ 正X
  （左）  ↓  （右）
        正Y（下）

原点 (0, 0) = 整张图的视觉中心
```

### 2.2 输出坐标的硬性规定

所有节点坐标都必须使用左上角坐标：

```text
NodeX = 节点左上角 X
NodeY = 节点左上角 Y
NodeWidth  = 节点宽度
NodeHeight = 节点高度
```

可以用中心点辅助计算，但最终输出必须回写为左上角坐标。

### 2.3 常用换算公式

```text
CenterX = NodeX + NodeWidth / 2
CenterY = NodeY + NodeHeight / 2

Right   = NodeX + NodeWidth
Bottom  = NodeY + NodeHeight

若已知目标中心点 (cX, cY)：
NodeX = cX - NodeWidth / 2
NodeY = cY - NodeHeight / 2
```

### 2.4 坐标输出规则

1. 最终 `NodeX / NodeY` 必须是整数
2. 不允许混用“中心点输出”和“左上角输出”
3. 只允许用中心点做中间推导，不允许直接拿中心点当最终坐标

## 三、数据字段

```text
| NodeID | NodeText | NodeType | ParentID | RelationText |
| NodeX  | NodeY    | NodeWidth | NodeHeight | NodeSemantic |
```

字段含义：

```text
NodeID        节点唯一标识
NodeText      节点显示文本
NodeType      节点类型
              DK = 主体知识节点
              PK = 结构/过程节点
              FC = 案例/实验/练习节点
              CS = 方法/建议/策略节点
ParentID      父节点ID；为空表示根节点或独立起点
RelationText  连线说明
NodeX/Y       节点左上角坐标
NodeWidth/Height 节点尺寸
NodeSemantic  节点语义说明
```

### 3.1 多入边节点

同一节点可能在表中出现多行，表示它有多个来源节点：

```text
| 163 | 定时器/计数器原理 | DK | 35  | 包含   | -356 | -56 | 115 | 69 |
| 163 | 定时器/计数器原理 | DK | 170 | 包含   | -356 | -56 | 115 | 69 |
| 163 | 定时器/计数器原理 | DK | 5   | 是前提 | -356 | -56 | 115 | 69 |
```

解释：

1. 节点 `163` 只有一个位置
2. 它的多行记录共用同一组 `NodeX / NodeY / NodeWidth / NodeHeight`
3. 不能因为有多个父节点，就给同一个节点生成多个位置

## 四、布局总原则

### 4.1 先骨架，后细节

布局顺序必须固定：

1. 根节点 / 中心节点
2. 一级主干节点
3. 一级主干下的二级簇
4. 多入边节点
5. FC / CS 外围节点
6. 整体居中与冲突检查

### 4.2 先给簇分区，再摆簇内节点

不要逐条边单独抢方向。正确方式是：

1. 先决定这个父节点的整个子簇放在哪个方向或象限
2. 再决定该子簇内部节点如何排布

也就是：

```text
先做区域决策，再做坐标决策
```

### 4.3 分区必须一眼可见

整张图必须能明显看出：

1. 中心主题在哪里
2. 左侧是哪一组
3. 右侧是哪一组
4. 上侧是哪一组
5. 下侧是哪一组

允许不完全对称，但不允许区域混乱。

### 4.4 子簇优先向外扩，不回穿中心

如果一个父节点已经位于某个方向，它的后代应优先继续向该方向外扩。

例如：

1. 父节点在左侧，子节点优先继续向左或左上/左下展开
2. 父节点在右侧，子节点优先继续向右或右上/右下展开
3. 父节点在上侧，子节点优先继续向上展开
4. 父节点在下侧，子节点优先继续向下展开

禁止出现“大量后代回穿中心”的情况。

## 五、节点类型的空间角色

### 5.1 DK / PK

`DK` 和 `PK` 是主体骨架，优先占据中心区和主轴区。

规则：

1. `DK` 优先靠近中心
2. `PK` 若承担结构展开，应给更大留白
3. 仍有后续出边的节点，不要塞到边缘角落

### 5.2 FC / CS

`FC` 和 `CS` 是外围补充节点，不进入主干密集区。

规则：

1. 必须放在关联主节点的更外侧
2. 不要插入两个主簇之间
3. 可以更偏、更远、更靠边

一个快速判断：

如果 `FC / CS` 比它关联的 `DK / PK` 更靠中心，通常就是摆反了。

## 六、推荐骨架模板

### 6.1 单中心放射型

适用：

1. 一个总主题
2. 若干一级主题
3. 一级主题下继续展开

建议：

1. 根节点放在中心附近
2. 一级节点分配到上、左、右、下和斜角
3. 二级簇沿一级节点外侧继续扩展

推荐一级节点中心位置模板：

```text
上      (0, -140)
左上    (-220, -140)
左      (-260, 0)
左下    (-220, 140)
下      (0, 140)
右下    (220, 140)
右      (220, 0)
右上    (220, -140)
```

说明：

1. 不必全部用满
2. 连接最强的一级节点优先放在上、左、右、下
3. 次级主题再放四个斜角

### 6.2 单主轴分区型

适用：

1. 存在明显主线流程
2. 其他节点是旁支补充

建议：

1. 主流程沿上到下或左到右排成主轴
2. 辅助簇挂在主轴两侧

### 6.3 双分区对峙型

适用：

1. 两大类知识对照
2. 左右两组都比较完整

建议：

1. 中间放总主题
2. 左右各放一个主簇
3. 上下再挂补充概念或案例

---

## 七、推荐间距与尺寸

优先使用以下稳定参数，不要临时大幅波动：

```text
一级节点半径：          140 ~ 180
一级到二级主簇距离：    120 ~ 180
同组兄弟横向间距：      110 ~ 160
同组兄弟纵向间距：       50 ~ 80
簇与簇最小间距：         80 ~ 160
FC / CS 外挂距离：      120 ~ 220
```

尺寸建议：

```text
根节点：    130~160 × 40~48
主干节点：  100~140 × 36~42
子节点：     80~120 × 32~38
外围节点：   90~130 × 32~38
```

补充原则：

1. 有后代的父节点，周围留白应更多
2. 同一组兄弟节点，间距尽量统一
3. 整张图宁可略松，不要拥挤

## 八、布局执行流程

### Step 1：识别结构骨架

先整理：

1. 哪些节点 `ParentID` 为空
2. 每个节点的入边列表
3. 每个节点的出边列表
4. 哪些节点是高连接度节点
5. 哪些节点是多入边节点

目标：

1. 选出一个视觉中心节点
2. 找出一级主干节点
3. 识别主要连接簇

### Step 2：选择骨架模板

在以下模板里选一个最贴近图结构的：

1. 单中心放射型
2. 单主轴分区型
3. 双分区对峙型

不要混杂多个模板导致整体失稳。必要时可以一个主模板加少量局部例外，但不能没有主结构。

### Step 3：给一级主干分配固定区域

一级主干先做区域分配，不要直接摆坐标。

示例区域约束：

```text
左侧簇：x < -120
右侧簇：x > 120
上侧簇：y < -100
下侧簇：y > 100
```

要求：

1. 一个一级簇的后代尽量留在本方向内
2. 除非确有强语义需要，不要跨中心去别侧展开

### Step 4：逐个父节点生成局部子簇

把每个父节点的子节点当作一个局部小布局来处理。

局部规则：

1. 先决定子簇主方向
2. 再决定同级兄弟如何排布
3. 优先让整个子簇待在父节点的外侧

### Step 5：选择同簇内部排布方式

同一父节点的多个子节点，优先使用以下三种方式之一：

1. 横向排开
2. 纵向堆叠
3. 2 列小矩阵

选择规则：

1. 子节点大多是叶子节点，优先横向排开
2. 子节点自己还有后代，优先纵向堆叠
3. 子节点很多时，允许使用 2 列小矩阵
4. 即便用矩阵，整个矩阵也必须保持在父节点同一侧

### Step 6：单独处理多入边节点

多入边节点不要完全服从某一个父节点的子簇。

规则：

1. 先计算其主要来源节点的视觉重心
2. 将节点放在这些来源之间或其外侧
3. 不要把它塞进某个单一簇的中心

若多入边节点还有后代：

1. 优先沿最主要的语义方向继续展开
2. 不要让其后代反向冲进多个来源节点之间

### Step 7：最后放置 FC / CS

`FC / CS` 必须最后处理。

规则：

1. 放在关联主节点的更外侧
2. 与关联主簇方向一致
3. 尽量贴边，不占主干之间的通道

### Step 8：整体居中

计算整体包围盒：

```text
minLeft
maxRight
minTop
maxBottom
```

要求：

```text
(minLeft + maxRight) / 2  接近 0
(minTop  + maxBottom) / 2 接近 0
```

若偏移明显，应整体平移一次，不要逐个节点碎调。

### Step 9：冲突检查与收尾

最后统一做：

1. 节点重叠检查
2. 簇间距检查
3. 连线穿越检查
4. FC / CS 外侧检查
5. 坐标整数化

---

## 九、局部排布规则

### 9.1 左侧簇

父节点在左侧时：

1. 子节点优先继续向左扩
2. 同级兄弟通常按 `Y` 从上到下排开
3. 若存在更深层后代，应继续向左延伸，不要折返

示意：

```text
        [子1]
[父] -> [子2]
        [子3]
```

### 9.2 右侧簇

父节点在右侧时：

1. 子节点优先继续向右扩
2. 同级兄弟通常按 `Y` 从上到下排开

### 9.3 上侧簇

父节点在上侧时：

1. 子节点优先继续向上扩
2. 同级兄弟通常按 `X` 从左到右排开

### 9.4 下侧簇

父节点在下侧时：

1. 子节点优先继续向下扩
2. 同级兄弟通常按 `X` 从左到右排开

### 9.5 斜角簇

父节点位于左上、右上、左下、右下时：

1. 子簇可沿同象限继续扩张
2. 主扩展方向只选一个
3. 另一方向只做小幅错位

例如右上簇：

1. 主要继续向右
2. 辅助上下错开 `40 ~ 70px`

不要同时大幅向上又大幅向右，否则簇会散开。

## 十、方向与坐标计算

这一节用于局部排布时的几何计算，优先服务于“已确定分区之后”的坐标求解，而不是替代分区决策。

### 10.1 判断相对方向

判断节点 B 相对节点 A 的主方向时，可用：

```text
若 B.Bottom <= A.Y，则 B 在 A 上方
若 B.Y >= A.Bottom，则 B 在 A 下方
若 B.Right <= A.X，则 B 在 A 左方
若 B.X >= A.Right，则 B 在 A 右方
```

若同时满足两个方向，按偏移更大的那个作为主方向：

```text
水平偏移 = |A.CenterX - B.CenterX|
垂直偏移 = |A.CenterY - B.CenterY|

水平偏移更大 → 主方向为左/右
垂直偏移更大 → 主方向为上/下
```

### 10.2 上下方向的水平展开

适用场景：

1. 子节点位于父节点上方
2. 子节点位于父节点下方

计算方式：

```text
父节点中心X = ParentX + ParentWidth / 2

同组总宽度 =
  所有子节点宽度之和 + (节点数 - 1) × 横向间距

第一个节点左上角X =
  父节点中心X - 同组总宽度 / 2
```

之后从左到右依次摆放。

### 10.3 左右方向的垂直展开

适用场景：

1. 子节点位于父节点左方
2. 子节点位于父节点右方

计算方式：

```text
父节点中心Y = ParentY + ParentHeight / 2

同组总高度 =
  所有子节点高度之和 + (节点数 - 1) × 纵向间距

第一个节点左上角Y =
  父节点中心Y - 同组总高度 / 2
```

之后从上到下依次摆放。

### 10.4 同方向多条出边时的规则

如果多个子节点都放在同一方向：

1. 叶子节点优先做整齐并排
2. 仍有后代的节点优先做纵向堆叠，给后续展开留空间
3. 混合类型时，`DK / PK` 靠内侧，`FC / CS` 靠外侧

## 十一、冲突检测

### 11.1 节点不能重叠

任意两个节点 A、B 至少要满足以下一项：

```text
A.Right + 20 <= B.X
B.Right + 20 <= A.X
A.Bottom + 12 <= B.Y
B.Bottom + 12 <= A.Y
```

### 11.2 簇之间要留通道

主簇之间至少留出 `80px` 可视通道，供连线和视线通过。

### 11.3 连线尽量不穿其他簇

父子连线应尽量只经过本簇，不要穿越别的簇中心区。

如果发生穿越，优先调整顺序：

1. 先平移整个簇
2. 再平移个别节点

### 11.4 外围节点必须更靠外

若 `FC / CS` 比其关联主节点更靠中心，则说明方向放反，必须重排。

---

## 十二、LLM 必须遵守的硬性规则

1. 不要逐条边贪心找方向后再拼起来
2. 必须先定骨架和簇分区，再给节点定坐标
3. 子节点不能大规模跨过父节点回穿中心
4. `FC / CS` 只能放在关联主节点外侧，不能塞进主干缝隙
5. 同组兄弟节点必须整齐对齐，不要每个节点随机偏移
6. 多入边节点只能有一个位置
7. 所有输出坐标必须是左上角整数坐标
8. 宁可略松，不要拥挤

---

## 十三、执行速查清单

每次生成布局时，按下面顺序执行：

```text
1. 识别根节点、一级主干、多入边节点
2. 选择一个主骨架模板
3. 给一级主干分配固定区域
4. 逐个父节点生成子簇
5. 为每个子簇选择横排 / 竖排 / 小矩阵
6. 放置多入边节点
7. 放置 FC / CS 外围节点
8. 做整体居中
9. 做重叠与通道检查
10. 输出整数左上角坐标
```

---

## 十四、给 LLM 的简化提示词

如果你是 AI，在生成关系图布局坐标时，按以下思路执行：

```text
1. 先找根节点或视觉中心节点
2. 选一个稳定的骨架模板，不要混用多个模板
3. 将一级节点先分配到上/左/右/下/斜角这些固定区域
4. 每个一级节点的后代只在本区域继续外扩，不回穿中心
5. 同一个父节点的多个子节点，优先做整齐排列，不要零散漂移
6. 多入边节点单独看重心，只保留一个位置
7. FC/CS 节点最后放，并且放在关联主节点的更外侧
8. 布局时可以用中心点辅助计算，但最终必须输出左上角整数坐标
9. 先保证分区清楚，再优化局部连线
```
