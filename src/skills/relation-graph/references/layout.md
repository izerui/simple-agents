# 布局参考

## 定位

这份文档用于指导 AI 把画布、坐标、节点分区、关系拓扑作为一个整体来规划。

目标不是“把节点摆开”，而是生成一张：
- 阅读路径清晰
- 主次层级明显
- 分区稳定
- 连线方向自然
- 可继续增量扩展

## 先规划，再落坐标

生成坐标前，先完成这 4 件事：

1. 识别主干
- 根节点是谁
- 一级主干节点有哪些
- 主阅读路径如何展开

2. 识别分组
- 哪些是步骤链
- 哪些是并列枚举
- 哪些是案例外挂
- 哪些是策略/方法辅助节点

3. 识别拓扑
- 哪些关系应短连
- 哪些关系应沿主阅读方向展开
- 哪些节点应贴近父节点
- 哪些节点应挂在外围

4. 规划画布区域
- 中心/中心偏左主干区
- 左侧步骤区
- 外缘枚举区
- 外围案例区
- 边缘策略区

不要边想边散点。先决定骨架，再填写 `x/y/width/height`。

## 坐标系

- 画布原点：`(0, 0)`
- `x` 向右增大，向左减小
- `y` 向下增大，向上减小
- 节点左上角由 `x/y` 定位
- 节点中心点为 `x + width / 2`、`y + height / 2`

任何布局判断都必须结合：
- `x`
- `y`
- `width`
- `height`

不要只看中心点。

## 版式骨架

### 主干区

适合放置：
- 根节点
- 一级核心概念
- 主阅读路径上的核心结构节点

要求：
- 根节点和一级主干优先放在中心或中心偏左
- 主干节点之间保持较大留白
- 主干负责建立整张图的骨架和阅读顺序
- 主干区不要塞入大量枚举和案例

### 步骤区

适合放置：
- `data.type = 3` 的程序性知识
- 流程、步骤、方法链路

要求：
- 优先形成左侧纵向步骤列
- 同一流程尽量共用稳定 `x`
- 节点顺序按 `y` 从上到下展开
- 不要让步骤链穿越主干区

### 枚举区

适合放置：
- 同父节点下的并列项
- 类型、组成、特征、分类、并列方法

要求：
- 同组节点统一横排或统一竖排
- 优先贴父节点外缘成组排列
- 同组方向必须一致
- 不要把同组节点打散到多个区域

### 案例区

适合放置：
- `data.type = 6` 的案例、示例、范例

要求：
- 优先挂在外围扇区
- 与依附知识点保持清晰挂接
- 位置优先在右侧、右下、下方、左下等外围区域
- 不要把案例塞回主干中部

### 策略区

适合放置：
- `data.type = 5` 的认知策略、方法提醒、学习策略

要求：
- 保持边缘辅助定位
- 不抢主干视觉中心
- 作为补充说明轻量挂接

## 拓扑规划

布局不仅是节点位置，还包括关系拓扑是否自然。

### 主阅读路径

主阅读路径应满足：
- 节点层级清楚
- 连线方向稳定
- 尽量短连
- 尽量少跨区

优先顺序：
- 主干到主干
- 主干到步骤/枚举
- 主干到案例/策略外围挂接

### 步骤链

步骤链应满足：
- 纵向连续
- 顺序稳定
- 连线方向优先 `bottom -> top` 或上一节点到底部、下一节点到顶部
- 整列视觉上像一条流程链

### 枚举组

枚举组应满足：
- 兄弟节点成组
- 间距一致
- 组内方向一致
- 父节点到子组的展开方向自然

### 外围挂接

案例和策略节点应满足：
- 贴近依附节点
- 挂在主干外侧
- 不穿越主阅读路径
- 连线像“外挂”而不是“并列主干”

## 尺寸与间距

### 尺寸

- `width` 和 `height` 必须直接给出
- 尺寸应与文本长度匹配
- 同组节点尺寸可不完全相同，但整体视觉要稳定

### 安全间距

- 任意两个节点最小安全间距：`20px`
- 节点不能重叠
- 连线文本较长时，应额外拉开间距

### 推荐间距

- 主干区水平间距：`120-220px`
- 主干区垂直间距：`80-160px`
- 组内水平间距：`60-120px`
- 组内垂直间距：`50-80px`
- 外围案例区与主干区额外预留：`80px+`

主干区留白应明显大于外围区，不要把所有节点均匀铺满画布。

## 坐标计算参考

### 子节点相对父节点的位置

- 右侧：`child.x = parent.x + parent.width + spacing`
- 左侧：`child.x = parent.x - child.width - spacing`
- 下方：`child.y = parent.y + parent.height + spacing`
- 上方：`child.y = parent.y - child.height - spacing`

### 多子节点成组

横向成组时：
- 先算总宽度
- 再以父节点中心为基准左右展开

纵向成组时：
- 先算总高度
- 再以父节点中心为基准上下展开

目的不是绝对对称，而是让同组节点：
- 间距均匀
- 展开方向统一
- 与父节点关系清楚

## 连接点选择

优先按相对方位选连接点：

- 目标在右侧：`right -> left`
- 目标在左侧：`left -> right`
- 目标在下方：`bottom -> top`
- 目标在上方：`top -> bottom`

补充规则：
- 步骤链优先上下连接
- 同层横向关系优先左右连接
- 外围挂接的案例/策略节点，连接点优先朝向主干一侧
- 难以判断时可使用 `border`

## 增量修改

增量时优先保持旧图稳定，不做整图重排。

要求：
- 旧节点尽量保持原坐标
- 新节点沿原有步骤列、枚举组、外围扇区方向追加
- 若原图已经形成稳定分组，新增节点优先尾插
- 不要为了加入一个新节点破坏整张图的骨架

增量优先策略：

1. 保持主干不动
2. 沿既有步骤列尾插
3. 沿既有枚举组侧插或尾插
4. 案例和策略优先向外围扩展

## 生成前自检

给出最终坐标前，至少检查：

1. 主干是否形成清晰骨架
2. 步骤节点是否形成稳定步骤列
3. 同父枚举是否成组且方向一致
4. 案例和策略是否位于外围
5. 是否有明显重叠、挤压、跨区穿插
6. 连线方向是否顺阅读路径
7. 整体是否保留了明显留白和层次
