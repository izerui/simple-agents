# 布局参考

## 定位

这份文档用于指导 AI 把画布、坐标、节点分区、关系拓扑、阅读顺序作为一个整体来规划。

目标不是“把节点摆开”，而是生成一张：
- 阅读路径清晰
- 主次层级明显
- 分区稳定
- 连线方向自然
- 适合增量扩展

`x/y` 不是随手填写的坐标，而是布局决策的最终结果。

## 使用顺序

生成坐标时按这个顺序思考：

1. 识别语义根和主干
2. 识别步骤链、枚举组、案例、策略
3. 规划画布区域和主阅读方向
4. 再填写 `x/y/width/height`
5. 最后检查连接点与整体可读性

不要边想边散点。先决定骨架，再落坐标。

## 语义根判断

“根节点”优先按语义中心判断，不要只按入度/出度机械判断。

原因：
- 有些图的关系方向是“叶子指向中心概念”
- 有些定义类、属性类关系会让中心节点看起来不是图论上的 root
- 模板图里就存在多个无入边节点，但真正的阅读中心仍然很明确

优先作为语义根的节点通常具备这些特征：
- 主题最总括
- 能统领多个一级分支
- 位于主阅读路径的中心位置
- 不是案例、不是策略、不是局部步骤项

如果用户显式给了 `rootId`，以用户提供内容为准。

## 坐标系

- 画布原点：`(0, 0)`
- `x` 向右增大，向左减小
- `y` 向下增大，向上减小
- 节点左上角由 `x/y` 定位
- 节点中心点为 `x + width / 2`、`y + height / 2`

任何布局判断都必须结合：
- `x`
- `y`
- `width`
- `height`

不要只看中心点。

## 画布与阅读方向

默认采用“中心主干 + 树内展开 + 外围挂接”的阅读结构。

统一要求：
- 不预设左侧、右侧、上方、下方或四个角的固定优先级；朝哪个方向展开，应由当前结构的清晰度决定
- 不要把多个分支压缩到同一个热点区域；无论放在哪个方向，都必须保证分列明确、逐层展开、走廊清楚
- 版式目标不是“尽量紧凑”，而是“主干、展开、外挂三者一眼可分”
- 树内展开优先走上下左右这四个正交方向，不要默认斜向展开
- 外挂优先走斜向外侧，避免和树内展开抢同一条主走廊
- 当节点总量增多时，可以继续向四周扩展新的展开区和外挂区，但新增区域仍要保持同样的结构清晰度
- 区域分布应尽量在四周看起来均衡，不要明显一边倒；左右和上下都要保持视觉平衡
- 这里的平衡不是机械对称，而是视觉重量接近、区域数量和密度接近、不会让某一侧明显过重而另一侧过空

推荐阅读顺序：
- 先看中心主干
- 再看树内展开链路
- 最后看外围案例与策略

但要注意：
- 主轴更适合承载主阅读链，而不适合持续承载大量 `1 对多` 或 `多对多` 连接
- 当一个高连接度节点同时连接多个并列分支时，优先把它们拆到多个分区或外围区域
- 不要把过多子节点继续堆在单一轴线或单一方向上，否则会让局部区域变成拥挤的汇流点
- 当单一区域已无法容纳所有子节点时，可以主动把部分节点拉远，开辟第二展开区继续分组与挂接
- 同一个父节点的 4 个以上子节点，不要继续塞进同一竖列或同一小区域；必须拆成多个分区、增加中间分组节点，或改成两段展开
- 如果某个区域已经出现明显密集堆叠、斜线回拉或多条边穿越主阅读走廊，说明该区域已超载，必须重新分区而不是继续微调坐标
- 单个父节点的子节点过多时，应先增加与父节点、兄弟节点、相邻分区之间的距离，开辟新区域后再继续按“正交展开、斜向外挂”的同一套偏好布置
- 开辟第二展开区时，迁移出去的那部分子节点应单独形成新的进入走廊；它们与父节点的连线要尽量绕开第一展开区，避免从原有子节点区域中间穿过

## 布局计算

布局时要主动计算，而不是凭感觉摆放。

至少同时计算这三类量：
- 间距：节点之间、组之间、主干与外围之间的留白
- 对齐：同组节点是否共享中心线、行基线或列基线
- 边距：节点到所属区域边界、父节点外缘、画布主要阅读走廊的安全距离

布局结果应满足：
- 同一分组内部的间距稳定
- 同一流程或枚举的对齐方式稳定
- 重要节点与区域边界之间保留呼吸感，不要贴边
- 各个区域之间必须彼此分离，不要互相重叠、互相压边或互相侵入
- 主干区、树内展开区、外围挂接区之间应保留清晰边界和走廊，不能因为局部拥挤就把区域叠在一起
- 全局视觉重心要尽量稳定，避免大部分节点、展开链或外挂都堆到同一侧，形成明显失衡

## 版式骨架

### 展开与外挂的区分

必须先判断节点属于“展开”还是“外挂”，两者不能混排：

- 展开：主知识树内部的层级展开，例如组成、类型、步骤、并列项、下位概念
- 外挂：案例、策略、说明、练习、补充示例等外围补充节点

硬规则：
- 展开节点必须保持树内对齐、成组、同方向扩展
- 外挂节点必须贴边、让出走廊、弱化存在感，不能挤进主干和展开组内部
- 不要把外挂节点当成普通兄弟节点去参与同一排布
- 不要让展开节点和外挂节点共用同一列、同一行带或同一拥挤区域
- 一旦一个区域同时出现“树内展开”和“外围外挂”，优先把外挂拉到更外层，而不是挤压展开组
- 先保树内展开清楚，再放外挂；必要时宁可让外挂更远，也不要破坏展开组的规整性
- 展开优先使用上下左右正交方向；外挂优先使用相对父节点或展开区的斜向外侧位置
- 每个区域都应视为一个独立包围区；区域包围区之间不得重叠

### 主干区

适合放置：
- 语义根节点
- 一级核心概念
- 主阅读路径上的核心结构节点

要求：
- 根节点优先放在全图的稳定锚点位置
- 一级主干围绕根节点建立稳定骨架
- 主干节点之间保持明显留白
- 主干区不要塞入大量案例和局部步骤

布局偏好：
- 主干优先形成 1 条清晰主轴，必要时再扩成 2 到 3 个一级分支
- 主干节点尽量避免上下左右同时大量发散
- 一级分支数量较多时，优先按语义拆成不同分区，不要挤在同一方向
- 若存在先决知识和案例节点，应与主干保持清晰分层，帮助形成稳定的视觉参照
- 若高连接度节点出现明显 `1 对多` 或 `多对多` 关系，优先做“一级展开 + 分区展开 + 外围挂接”，不要把多个子节点都压在同一主轴或同一延长线上
- 若第一展开区已拥挤，优先把次级节点迁移到第二展开区，而不是继续在原区域硬塞

### 步骤区

适合放置：
- `data.type = 3` 的程序性知识
- 流程、步骤、方法链路、操作顺序

要求：
- 优先形成单方向、连续、稳定的步骤列
- 同一流程尽量共用稳定的轴线
- 节点顺序按 `y` 从上到下展开
- 不要让步骤链穿越主干区

布局偏好：
- 同一条步骤链尽量使用单列
- 如果步骤过多，优先纵向拉长，不要轻易折返成 Z 字
- 步骤列与主干区之间保留明显走廊，避免连线与主干节点互相穿插
- 如果步骤链连线上需要显示关系文本，纵向间距要优先保证“连线 + 文字”都清楚可见，不能只够放文字
- 步骤链节点之间宁可更疏，也不要让短连线几乎看不见
- 如果步骤链依附于某个流程节点，优先让步骤列沿独立走廊连续展开，而不是与主干抢同一拥挤带
- 如果流程节点与其下属步骤链之间没有明显避让冲突，优先让流程节点与步骤列共享同一垂直中心线

### 枚举区

适合放置：
- 同父节点下的并列项
- 类型、特征、组成、分类、模式、并列方法

要求：
- 同组节点统一横排或统一竖排
- 优先贴父节点外缘成组排列
- 同组方向必须一致
- 不要把同组节点打散到多个区域

布局偏好：
- 枚举组优先放在父节点外缘最清楚、最不拥挤的一侧
- 如果父节点附近已有拥挤区，枚举组应主动避开，改在更清楚的方向展开
- 枚举数量较少时优先横排；数量较多或标签较长时优先竖排
- 多个并列节点需要对齐时，优先对齐中心点而不是只对齐左上角
- 如果画布空间充足，同组并列节点要做成明显规整的行列，不要只满足“大致在同一侧”
- 单个枚举组超过 4 项时，优先改成 2 列、分块分组或“组节点 -> 子项”两级展开，不要无脑堆成一条超长竖列
- 如果当前展开区已经存在另一条主链或外挂链，不要再把新的枚举组压到同一区域上，应主动开辟新的展开区

### 案例区

适合放置：
- `data.type = 6` 的案例、示例、范例、应用实例

要求：
- 优先挂在外围扇区
- 与依附知识点保持清晰挂接
- 位置应在主干和树内展开之外的外围区域
- 不要把案例塞回主干中部

布局偏好：
- 案例节点默认视为“外挂说明”，不是并列主干
- 如果一个知识点挂多个案例，案例之间应沿同一外缘方向展开
- 案例与主干之间保留额外空白，保证它们看起来像外围补充而非主轴竞争者
- 案例外挂优先挂在展开区外侧，不能插入展开组的行列内部
- 如果外挂节点会压缩展开组间距，优先把外挂整体外移，而不是缩小展开组

### 策略区

适合放置：
- `data.type = 5` 的认知策略、学习建议、方法提醒、使用建议

要求：
- 保持边缘辅助定位
- 不抢主干视觉中心
- 作为补充说明轻量挂接

布局偏好：
- 策略节点优先贴依附节点外缘放置
- 如果案例和策略同时存在，策略应比案例更靠边、更轻
- 策略外挂与案例外挂要继续向外分层，不要反向挤占树内展开的主走廊

## 区域优先级

默认区域优先级如下：

1. 稳定锚点区：语义根、一级主干
2. 树内展开区：步骤链、程序性知识、枚举组、模式、组成、分类
3. 外围挂接区：案例节点
4. 最外层辅助区：策略节点

如果内容与这个模式冲突，以语义可读性优先，但不要无理由打破分区。

## 拓扑规划

布局不仅是节点位置，还包括关系拓扑是否自然。

通用原则：
- 高连接度节点要做分区展开
- 连接点要按节点外缘最近落点选择
- 两者必须同时成立，不能只优化其中一项
- 语义连接必须优先组织成主知识树，不要把图做成网状互连
- 案例、策略、练习类节点默认只做外围叶子挂接，不参与主树回连
- 如果一条补充关系会明显破坏分区或带来交叉，优先删除该边或改成重新分组
- 连线不能穿过密集节点区、主干核心区或兄弟节点组内部；一旦出现明显穿越，优先重排分区，而不是接受“能连上就行”
- 主干两侧应保留走廊，连线优先沿走廊进出，不要从拥挤区域斜穿多个节点组

### 主阅读路径

主阅读路径应满足：
- 层级清楚
- 连线方向稳定
- 尽量短连
- 尽量少跨区
- 优先保持单主链向外展开，而不是多分支之间互相回连

优先顺序：
- 主干到主干
- 主干到步骤/枚举
- 主干到案例/策略外围挂接

布局偏好：
- 主阅读路径上的相邻节点，视觉距离应小于跨分区节点
- 主阅读路径不要被案例或策略节点截断
- 优先先建立一棵稳定的主知识树，再处理外围语义补充
- 不要为了表达“有关联”就直接在不同分支之间补边，否则很容易退化成网状结构
- 确有跨分支语义时，优先通过重新归类、提升层级、增加中间分组节点或外围挂接处理

### 步骤链

步骤链应满足：
- 纵向连续
- 顺序稳定
- 连线方向优先 `bottom -> top`
- 整列视觉上像一条流程链

布局偏好：
- 单条步骤链内尽量不要混入非步骤节点
- 步骤节点高度可略有差异，但列中心应稳定

### 枚举组

枚举组应满足：
- 兄弟节点成组
- 间距一致
- 组内方向一致
- 父节点到子组的展开方向自然

布局偏好：
- 同一枚举组优先共享一个“行基线”或“列基线”
- 如果一个父节点同时有步骤链和枚举组，枚举组不要挤占步骤列

### 外围挂接

案例和策略节点应满足：
- 贴近依附节点
- 挂在主干外侧
- 不穿越主阅读路径
- 连线像“外挂”而不是“并列主干”
- 默认作为叶子节点使用，不再回连主树中的其他节点

### 高连接度拆层

当一个节点的一级子节点过多时，应优先拆层，不要把所有内容直接压在同一层展开。

要求：
- 一级子节点较多时，优先先建立二级分组节点，再展开具体知识点
- 不要让一个中心节点同时直接承载大量步骤、枚举、案例、策略和前提节点
- 局部需要拉远时，允许开辟第二展开区继续分组与挂接

布局偏好：
- 一级分支超过 `4-6` 个时，优先考虑拆成二级分组
- 根节点或主干节点不要直接挂出过多并列节点
- 拆层后优先保持“主干清楚、分组稳定、外围轻量”的阅读感
- 被迁移到第二展开区的子节点，不是随便放远一点就结束；它们的连线也要和第一展开区分流，避免斜穿第一展开区或从旧节点组内部交叉

## 尺寸与间距

### 尺寸

- `width` 和 `height` 必须直接给出
- 尺寸应以“刚好包住节点文字内容”为原则，不要无理由做得过宽或过高
- 同组节点尺寸可不完全相同，但整体视觉要稳定
- 节点文字四周应预留少量内边距，让文字不要贴边
- 文本较长时优先适度增大宽度；只有宽度继续增加会明显破坏布局时，再增高换行承载

### 安全间距

- 任意两个节点最小安全间距：`20px`
- 节点不能重叠
- 连线文本较长时，应额外拉开间距
- 节点与所属区域或容纳边界之间至少保留 `30px` 安全边距
- 不同区域的包围边界之间至少保留 `40px` 安全间距

### 推荐间距

- 主干区水平间距：`120-220px`
- 主干区垂直间距：`80-160px`
- 步骤列垂直间距：`45-80px`
- 若步骤链连线显示关系文本，优先提高到 `70-120px`
- 组内水平间距：`60-120px`
- 组内垂直间距：`50-80px`
- 外围案例区与主干区额外预留：`80px+`
- 策略节点到依附节点的外缘偏移：`80-140px`

主干区留白应明显大于外围区，不要把所有节点均匀铺满画布。

## 坐标生成偏好

### 程序化定位规则

需要程序化判断对齐或落点时，优先用中心点而不是只看左上角：

- 水平中心：`x + (width / 2)`
- 垂直中心：`y + (height / 2)`

适用规则：
- 多个节点横向排布时，优先让它们的垂直中心一致
- 多个节点纵向排布时，优先让它们的水平中心一致
- 同一枚举组或步骤列如需严格对齐，优先匹配中心坐标，再微调左上角坐标
- 父节点带一组子节点时，优先按父节点中心线展开，而不是机械贴齐父节点左边或上边

### 主干落点

主干落点时优先：
- 先放语义根
- 再放一级主干
- 再放二级支撑节点

推荐做法：
- 先给根节点预留中心位置
- 按阅读顺序把一级分支布到最清楚、最不拥挤的主区域
- 只有在内容明显需要且不会破坏整体清晰度时，才把重要节点放到特殊方向的锚点位置

### 子节点相对父节点的位置

- 右侧：`child.x = parent.x + parent.width + spacing`
- 左侧：`child.x = parent.x - child.width - spacing`
- 下方：`child.y = parent.y + parent.height + spacing`
- 上方：`child.y = parent.y - child.height - spacing`

经验偏好：
- 步骤节点优先放在能形成连续流程列的方向
- 枚举节点优先放在能形成规整并列组的方向
- 案例/策略优先放父节点外缘

### 多子节点成组

横向成组时：
- 先算总宽度
- 再以父节点中心为基准左右展开

纵向成组时：
- 先算总高度
- 再以父节点中心为基准上下展开

目的不是绝对对称，而是让同组节点：
- 间距均匀
- 展开方向统一
- 与父节点关系清楚
- 中心线尽量稳定

优先级补充：
- 先保证组内对齐和分布规整
- 再保证与父节点的连接自然
- 最后才为局部避让做小幅偏移

### 新增节点落点顺序

当一个新节点存在多个可落点区域时，优先级如下：

1. 延续原有分组方向
2. 延续原有步骤列或枚举组的尾部
3. 选择不会切断主阅读路径的位置
4. 选择连线更短的位置
5. 选择更外围的位置，而不是挤占主干

## 连接点选择

优先按相对方位选连接点：

- 目标在右侧：`right -> left`
- 目标在左侧：`left -> right`
- 目标在下方：`bottom -> top`
- 目标在上方：`top -> bottom`

补充规则：
- 步骤链优先上下连接
- 同层横向关系优先左右连接
- 外围挂接的案例/策略节点，连接点优先朝向主干一侧
- 难以判断时可使用 `border`
- 连线方向应自然，不要明显穿过节点主体或破坏主阅读路径
- 如果关系文本显示在线路附近，应优先避免文本压住节点，或落在拥挤交叉区域
- 当两个节点在上下方向更接近，且上下连接明显短于左右连接时，优先使用 `bottom -> top`
- 当两个节点在左右方向更接近，且左右连接明显短于上下连接时，优先使用 `left/right` 侧连接
- 连接点选择优先依据“节点外缘最近落点”，不是只按节点大致位于哪个象限

对于复杂 `1 对多 / 多对多` 结构，额外要求：
- 子节点分区展开后，连接点也要同步跟着分区方向调整
- 优先让单条连线更短、更顺、交叉更少
- 第二展开区或更外层分区的连线，优先从父节点空旷的一侧进出，并沿新区自己的走廊连接；不要让这些连线穿越第一展开区
- 不要出现“节点已经分区展开，但连线仍从不自然的一侧出入”的情况
- 当一个分区中的节点数继续增加时，可以允许部分连线距离变长，以换取第二分区的清晰展开和整体可读性
- 多个分区之间不要再互相补跨线，分区一旦拆开，应继续保持树状向外展开

## 增量修改

增量时优先保持旧图稳定，不做整图重排。

要求：
- 旧节点尽量保持原坐标
- 新节点沿原有步骤列、枚举组、外围扇区方向追加
- 若原图已经形成稳定分组，新增节点优先尾插
- 不要为了加入一个新节点破坏整张图的骨架

增量优先策略：

1. 保持主干不动
2. 沿既有步骤列尾插
3. 沿既有枚举组侧插或尾插
4. 案例和策略优先向外围扩展

## 常见坏味道

以下情况通常说明布局质量不够好：

- 只因为局部拥挤就把主干节点甩到外围
- 步骤节点横向来回折返
- 同组枚举节点有的横排、有的竖排
- 案例节点落在主干中心区域
- 策略节点比主干节点更靠中心
- 主阅读路径被长跨线切断
- 画布四周很空，但中心过度拥挤
- 多个分支之间互相补线，形成网状结构
- 同一节点同时挂接多个父节点，导致阅读路径不再唯一

## 布局参考样例

`references/layout-example.md` 可作为现有图谱的布局参考样例，用于观察：
- 主干、步骤列、枚举组、案例外挂的大致分区方式
- 常见节点尺寸、纵列间距、外围案例放置方式
- 不同语义类型在画布中的相对位置

它主要用于参考结构组织与布局风格，同时也可作为 `graph.md` 文件样本，不参与正式生成流程，也不是结构权威。

冲突处理优先级：
1. 用户当前任务的内容与增量约束
2. 本文档
3. `references/layout-example.md`

## 生成前自检

给出最终坐标前，至少检查：

1. 是否先按语义而不是仅按图论入度找到了根节点
2. 主干是否形成清晰骨架
3. 步骤节点是否形成稳定步骤列
4. 同父枚举是否成组且方向一致
5. 案例和策略是否位于外围
6. 是否有明显重叠、挤压、跨区穿插
7. 连线方向是否顺阅读路径
8. 主阅读路径是否被外围节点打断
9. 整体是否保留了明显留白和层次
