# 课程设计 JSON 结果文件生成

## 任务目标

你的目标不是解释思路，而是**产出最终课程设计 JSON**。

默认交付物应满足以下条件：
- 可被直接保存为 JSON 文件
- 根结构与 `references/demo.json` 一致
- 中文字段名稳定，不擅自改名
- 内容覆盖学习目标、先决知识、资源、时间、活动序列、活动详情、任务详情、评价标准、备注

如果用户只说“帮我生成教学设计/课程设计/教案 JSON/按 demo.json 输出”，直接按本技能执行。

## 何时触发

遇到以下场景应使用本技能：
- 用户要“生成课程设计 JSON”“输出教学设计结果文件”“按固定 JSON 结构生成教案”
- 用户给出课程名称、学时、专业、任务内容，希望你补全完整教学设计
- 用户给出知识建模图 JSON，希望据此生成教学设计其余部分
- 用户要求输出类似 `demo.json` 的课程设计最终结果
- 用户明确要求产出可落库、可存档、可交付的教学设计结构化数据

以下情况不要把结果停留在自然语言：
- 只给大纲
- 只给 Markdown 教案
- 只给局部字段
- 只解释怎么设计

## 先收集信息

### 必填信息
若缺失，先追问：
- 课程名称
- 课程设计名称 / 教案名称 / 周次课次
- 学时安排（需明确课上 / 课下）
- 课程类型
- 教学形式
- 适用专业
- 学生层次
- 任务内容

### 选填信息
有就吸收，没有也要继续生成：
- 知识建模图 JSON
- 教材页码、课件、讲义、案例、题库、作业模板
- 评价重点
- 课程思政点
- 教学资源清单
- 用户提供的结果样例

## 输入资料使用原则

### 1. 用户资料是增强项，不是唯一前提
- 有资料：提炼并吸收有效信息
- 无资料：仍依据课程名称、学时、任务内容、专业背景独立生成

### 2. 若提供知识建模图 JSON
重点读取：
- `nodes`：识别知识点、案例、先决知识、思政点
- `lines`：识别关系，至少理解 `from`、`to`、`text`

常见关系包括：
- `支持`
- `具有特征`
- `内容包含`
- `步骤包含`
- `是前提`
- `关键点包含`

常见节点类型与映射方式：

#### 核心知识点
通常对应：
- 学习目标中的核心知识点
- 活动目标中的重点内容
- 课上任务中的主要学习对象

#### 结构化知识框架
通常对应：
- 步骤、流程、方法、工作链路
- 第二类课程中的能力目标支撑
- 任务拆分依据

#### 先决知识
通常对应：
- `学习先决知识`
- 各活动导入任务中被唤醒的旧知

#### 案例 / 资源 / 思政点
通常对应：
- 课上 / 课下资源
- 任务中的学习资源
- 素质目标（课程思政点）

映射原则：
- 核心知识点 → 学习目标 / 活动目标
- 先决知识 → 学习先决知识 / 导入任务
- 步骤或流程 → 活动切分 / 任务序列 / 能力目标
- 案例与素材 → 学习资源
- 思政点 → 素质目标（课程思政点）

你不需要把知识建模图重新设计成另一种格式；只需把它转化为课程设计 JSON 中需要的目标、活动、任务与资源。

### 3. 固定字段中的“知识建模图”
结果 JSON 中保留 `知识建模图` 字段，因为它是 `demo.json` 的固定结构之一。
- 若用户提供了相关图片/图示，可放入 `images`
- 若没有，按 `references/demo.json` 风格保留占位结构：

```json
{
  "key": "知识建模图",
  "value": "知识建模图：\n",
  "images": []
}
```

### 4. 使用边界
- 不要为了“解释建模图”而偏离最终交付物
- 不要输出另一套独立的知识建模图说明文档代替课程设计 JSON
- 若图中信息不全，可结合课程名称、任务内容、学时安排继续补全教学设计

## 课程类型适配

### 两类课程
- 第一类：应用型研究方向项目化教学课程 / 专业基础课程 / 公共基础课程
- 第二类：就业方向项目化教学课程

### 学习目标差异
- 第一类课程：`知识点（学习水平）` + `素质目标（课程思政点）`
- 第二类课程：`知识点（学习水平）` + `能力目标` + `素质目标（课程思政点）`

### 学科表达适配
- 理工类：公式用 LaTeX，特殊符号用 Unicode
- 文史类：强调规范表达、阅读材料、讨论与写作任务
- 政治类：坚持正确价值导向，避免不当敏感表述
- 艺术类：可加入图像、案例、素材等多模态资源

## 输出结构要求

最终输出必须是一个完整 JSON 对象：

```json
{
  "标题": "课程标题",
  "课程设计名称": "课程设计名称",
  "课程设计": [],
  "活动序列": {}
}
```

### `课程设计` 数组必须按顺序包含 8 个板块
1. `学习目标`
2. `学习先决知识`
3. `知识建模图`
4. `课上资源`
5. `课下资源`
6. `课上时间`
7. `课下时间`
8. `活动序列`

### 根层 `活动序列` 必须展开活动详情
每个活动下至少包含：
- `知识建模图`
- `活动任务序列（导入任务描述）`
- `活动目标`
- `师生交互过程`
- `活动任务序列（任务）`

### 每个任务对象至少包含
- `任务名称`
- `知识组块`
- `任务描述`
- `任务时长`
- `学习地点`
- `教学方式（或学习方式）`
- `师生交互过程`
- `学习资源`
- `学习成果及评价标准`
- `备注`

## 生成原则

1. 先保证**结构完整**，再优化内容质量。
2. 学习目标、活动目标、任务内容、资源、评价标准必须相互对应。
3. 活动切分要合理，能支撑课堂推进与课下延伸。
4. 课上与课下时间总和要与活动明细一致。
5. 师生交互过程要具体到同专业教师可直接参考上课。
6. 评价标准要可执行、可观察、可判定。
7. 缺失项可用 `""`、`/`、空数组等占位，但不能破坏结构。
8. 输出优先服务结果交付，不要夹杂长篇解释。

## 教学设计质量要求

### 第一类课程
必须包含：
- `知识点（学习水平）`
- `素质目标（课程思政点）`

### 第二类课程
必须包含：
- `知识点（学习水平）`
- `能力目标`
- `素质目标（课程思政点）`

### 学习水平
统一使用：
- 记忆
- 理解
- 运用

写法要求：
- 按 `知识点（学习水平）` 撰写
- 每个知识点只保留最高层次学习水平
- 知识点要覆盖本次课程核心内容

### 能力目标
仅第二类课程需要。
能力目标应对应真实任务能力，例如：
- 能够独立完成××任务
- 能够制定××实施方案
- 能够执行××流程
- 能够完成××效果评测
- 能够识别并解决××常见问题

### 素质目标（课程思政点）
要求：
- 与课程内容紧密相关
- 与具体教学活动有落点
- 有明确思政点时用 `*` 标注
- 没有可填 `/`

## 字段填写规则

### 学习目标
- 知识点按 `知识点（学习水平）` 撰写
- 学习水平只用：`记忆`、`理解`、`运用`
- 每个知识点保留最高层次学习水平
- 第二类课程补充 `能力目标`
- `素质目标（课程思政点）` 要与课程内容和活动落点相关；有明确思政点时用 `*` 标注，没有可填 `/`

### 学习先决知识
- 写完成本次学习前必须具备的基础知识
- 按 `知识点（学习水平）` 撰写
- 直接服务导入任务与后续活动展开

### 资源与时间
- 课上资源、课下资源分别汇总
- 资源名称尽量具体到教材页码、视频、平台题目、模板、素材
- 时间统一用“分钟”
- `课上时间` 与所有课上活动时间总和一致
- `课下时间` 与所有课下活动时间总和一致

### 活动序列（课程设计数组中的板块）
- 每个活动通常包含课上、课下两条记录
- 每条记录都写：`活动目标`、`地点`、`时间`、`学习资源`
- 使用 `sorted_names` 标明活动顺序

### 活动目标
- 列出该活动覆盖的核心知识点
- 按 `知识点（学习水平）` 撰写
- 与总学习目标保持一致

### 导入任务描述
- 围绕先决知识唤醒设计
- 重点是建立联系、引出新内容
- 时长一般控制在 5 分钟左右
- 若活动之间无需单独导入，可写 `""` 或 `/`

推荐格式：

```text
教师：回顾与本课直接相关的先决知识，提出导入问题。
学生：回忆旧知，结合已有经验回答。
教师：追问、比较、建立联系，引出本活动新内容。
学生：讨论、补充、形成学习期待。
教学策略：经验连接法、问题引导法、情境创设法
```

### 任务描述
按这个逻辑写：
> 因为何种教学思考或学习难点，采用什么教学策略，达到什么学习结果。

### 学习地点
一个任务只对应一种地点：
- 课上
- 课下

### 教学方式（或学习方式）
必须保留以下结构：
- `key`
- `value`
- `checkbox`
- `checkbox_other`

要求：
- `checkbox[0]` 为固定选项列表
- `checkbox[1]` 为被选中的索引数组
- 若有补充方式，写入 `checkbox_other`

### 知识组块
保留如下结构：
```json
{
  "key": "知识组块",
  "value": "任务一知识组块：\n",
  "images": []
}
```

要求：
- 每个任务都必须有知识组块
- 知识组块与任务一一对应
- 可用占位结构，也可填写具体知识内容

## 师生交互过程要求

### 通用原则
1. 采用时间线式描述。
2. 每一轮互动都同时写教师行为和学生行为。
3. 体现具体教学策略，而不是空泛口号。
4. 写出关键引导语、追问语、总结语。
5. 教师行为要具体可操作，学生行为要具体可观察。
6. 尽量避免只有简单问答，要让学生发生比较、分类、归纳、演绎、应用等思考。
7. 目标是让同专业教师看到后可直接参考上课。

### 任务内交互推荐格式

```text
1. 教师：……（采用××教学策略）
   学生：……
2. 教师：……（运用××教学策略）
   学生：……
3. 教师：……（总结归纳 / 评价反馈 / 布置任务）
   学生：……
教学策略：××法、××法
```

### 课下任务特别要求
课下任务的交互重点不是全过程陪伴，而是**任务布置时的关键互动**。通常应包含：
- 任务要求说明
- 资源提供
- 疑问解答
- 时间要求
- 提交方式

写法要求：
- 以学生执行行为为主，教师部署与指导为辅
- 教学策略应包含 `自主学习法`
- 可补充 1-2 种策略：项目驱动法、任务驱动法、实践练习法、探究式学习法、翻转课堂法

### 常见教学策略

#### 帮助理解
- 案例分析法
- 对比分析法
- 引导发现法
- 归纳总结法
- 情境创设法
- 问题引导法
- 经验连接法
- 示范法
- 分层练习法
- 个别辅导法

#### 帮助记忆
- 顺口溜法
- 关联记忆法
- 重复记忆法
- 图表记忆法

#### 帮助运用
- 实践练习法
- 任务驱动法
- 项目教学法
- 反思总结法
- 人机协同法
- 探究式学习法
- 翻转课堂法

### 师生交互快速自检
- 是否每一轮都有教师与学生两端行为
- 是否能看出采用了什么教学策略
- 是否出现了明确的引导、追问、总结
- 是否与任务描述和教学方式逻辑一致
- 若是课下任务，是否写清了要求、资源、时间、提交方式

## 学习成果及评价标准

要求：
- 每个任务都要有明确学习成果
- 必须与知识目标、能力目标对应
- 评价标准要具体、客观、可操作
- 建议 `学习成果及评价标准.value` 使用数组结构
- 尽量允许学生修改并再次提交
- 评价标准最好提前告知学生

### 记忆类知识点
若任务包含记忆层次内容，学习成果宜设计为：
- 选择题
- 填空题
- 判断题
- 简答题

评价原则：
- 答对得分
- 答错得 0 分
- 明确标注正确答案和分值

## 备注

可包含：
- 教学心得
- 教学反思
- 学情信息
- 学生常见问题
- 需要重点关注的学生特征
- 学生有效学习方法
- 学生反馈与建议

要求：
- 具体
- 有诊断价值
- 能指导后续教学改进

## 输出前检查

生成最终结果前，逐项检查：
- `标题`、`课程设计名称`、`课程设计`、`活动序列` 四个根层字段完整
- `课程设计` 数组中的 8 个板块完整且顺序正确
- `课程设计` 中的 `活动序列.value` 与根层 `活动序列` 活动名称一致
- `sorted_names` 与实际活动键一致，且无多余换行或空格
- 学习目标、活动目标、任务设计、资源、评价标准前后对应
- 课上 / 课下时间与活动明细总和一致
- 每个活动都有活动目标
- 每个活动都有导入任务描述或合理占位
- 每个活动都有任务数组
- 每个任务都有教学方式字段结构
- 每个任务都有师生交互过程
- 每个任务都有学习成果及评价标准
- 每个任务都有备注
- 第二类课程包含 `能力目标`
- JSON 可正常解析
- 字段名称、嵌套层级、数组结构尽量对齐 `references/demo.json`

## 最终输出方式

### 若信息不足
先简短追问缺失的必填信息，不急着输出半成品 JSON。

### 若信息已足够
直接输出最终 JSON，不额外附加长篇说明。

### 禁止事项
- 不要只输出大纲
- 不要只输出 Markdown 教案
- 不要省略根层 `活动序列`
- 不要把任务写成纯段落导致字段结构丢失
- 不要随意修改固定中文字段名
- 不要让 `checkbox` 结构失效
- 不要生成与 `references/demo.json` 明显不一致的层级

## 保留参考

- `references/demo.json`：最终结果文件结构基准
