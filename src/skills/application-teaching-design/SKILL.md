# 课程设计最终 JSON 生成

## 任务目标

你的目标不是解释思路，而是直接产出最终 JSON。

默认要求：
- 严格符合 `references/schema.json`
- 面向解析、校验、前端回填和导入接口映射
- 所有结构字段都以 schema 定义的对象、数组、整数或字符串类型输出

## 关联文件

- `references/schema.json`
  - 最终输出的唯一结构基准
  - 需要确认字段结构、类型、必填项、数组形式、枚举值时，优先看这个文件
- `references/example.json`
  - 新版结构示例
  - 需要参考字段组织方式、活动层与任务层的组合方式时，看这个文件，但不要机械照抄示例内容
- `scripts/validate_json.py`
  - 本技能的校验脚本
  - 生成结果后可用它校验 schema 合法性和部分业务约束
  - 用法：`python3 /skills/application-teaching-design/scripts/validate_json.py /path/to/result.json`

使用顺序：
- 先按本 `SKILL.md` 理解生成规则与前端口径
- 再以 `references/schema.json` 约束最终结构
- 需要参考组织方式时再看 `references/example.json`
- 产出 JSON 后用 `scripts/validate_json.py` 校验

## 必填信息

缺失时先追问：
- 课程名称
- 课程设计名称 / 周次课次
- 学时安排（课上 / 课下）
- 课程类型
- 教学形式
- 适用专业
- 学生层次
- 任务内容

## 选填信息

有就吸收，没有也继续生成：
- 知识建模图 JSON / 图示
- 教材、课件、案例、作业模板、题库
- 课程思政点
- 评价重点
- 资源链接或附件信息

## 各模块该生成什么

以下规则描述的是各模块的生成口径与展示语义。
最终输出时，仍必须按 `references/schema.json` 的结构化字段落地，不要直接把整句“知识点（学习水平）”塞进不该放字符串的结构字段。

### 学习目标
- 生成“知识点（学习水平）”语义内容
- 第一类课程：再生成“素质目标（课程思政点）”
- 第二类课程：还要生成“能力目标”
- 学习水平只用：`记忆` / `理解` / `运用`
- 展示语义可理解为：`知识点（学习水平）`
- 最终 JSON 中仍按知识点对象落地：`{ 名称, 学习水平, 说明 }`

### 学习先决知识
- 只罗列知识建模图中绿色先决知识点
- 展示语义同样可理解为：`知识点（学习水平）`
- 最终 JSON 中仍按知识点对象落地：`{ 名称, 学习水平, 说明 }`

### 课上资源 / 课下资源
- 生成分类汇总结果，不是散乱罗列
- 常用分类可包括：`视频/短片`、`教具`、`教学课件`、`素材库`、`参考书`、`网络资源`
- 资源要具体到名称，最好能落到具体页码、片段、案例

### 课上时间 / 课下时间
- 只生成总时长
- 必须和后面活动、任务时长总和一致

### 活动序列
- 每个活动生成：活动目标 + 地点 + 时间 + 学习资源
- 活动目标仍然按“知识点（学习水平）”语义组织
- 一个活动应相对完整，便于学生消化

### 活动知识建模图
- 生成当前活动覆盖的知识点裁剪图
- 不能比活动任务多，也不能少
- 仍保留知识关系表达，如：`支持` / `具有特征` / `内容包含` / `步骤包含` / `是前提`

### 活动目标
- 生成本活动知识建模图里除先决知识外的全部知识点
- 每个知识点都要标最高学习水平

### 导入任务描述
- 不是讲新知识主体，而是唤起先决知识、引出本次内容
- 时长宜短，约 5 分钟
- 重点写典型引导语和师生互动

### 任务描述
- 固定生成逻辑：
  - 因为何种思考或原因
  - 采用什么教学策略
  - 达到什么学习结果
- 本质上是在交代“为什么这样教”

### 教学方式（或学习方式）
- 从 `讲授`、`小组讨论`、`答疑`、`实验`、`实训`、`自主学习`、`翻转课堂`、`其他` 中选择
- 必须和任务描述、教学策略一致

### 学习资源
- 生成当前任务直接使用的资源
- 不是全课资源汇总，而是任务级资源

### 学习成果及评价标准
- 必须同时生成“学习成果”“评价标准”“评价方式”
- 学习成果要能观察、能提交、能评价
- 评价标准要具体、可测、可操作

### 备注
- 生成教学反思和学情信息
- 可包括常见问题、需关注学生、有效学习方法、学生反馈等

## 输出结构

最终 JSON 顶层固定为：

```json
{
  "标题": "",
  "课程设计名称": "",
  "课程信息": {},
  "学习目标": {},
  "学习先决知识": [],
  "知识建模图": {},
  "课上资源": [],
  "课下资源": [],
  "活动序列": []
}
```

## 核心建模规则

### 总原则
- 如果提供了知识建模图，所有内容都应尽量基于已有知识建模图生成，不能遗漏核心知识
- 活动级 `知识建模图` 只能是总知识建模图的合理裁剪，不应扩展出总图之外的核心知识范围
- 任务级 `知识建模图` 只能是活动知识范围内的进一步聚焦，不应偏离所属活动的知识边界
- 各模块之间必须一致：知识点、活动目标、任务、资源、评价、时间要互相对应
- 核心知识点尽量放在课上任务中
- 难点、易错点、需要教师引导的内容尽量放在课上任务中

### 0.1 勾选类字段统一规则
- 凡是前端以勾选框呈现的数组字段，都按“允许多选，但至少选一个”处理
- 目前本技能中明确属于这类规则的字段包括：各类知识点对象中的 `学习水平`、任务中的 `教学方式.方式`
- 不要把勾选类字段降级成单个字符串

### 0. 学习目标按前端三栏口径生成
- `学习目标` 固定分为 `知识目标`、`能力目标`、`素质目标`
- `知识目标` 对应前端“知识点目标（学习水平）”
- `能力目标` 对应前端“能力目标”
- `素质目标` 对应前端“素质目标（课程思政点）”

### 1. 活动必须是数组
- `活动序列` 是数组
- 每个活动必须有 `活动id`、`排序`、`活动名称`
- 每个活动都是 `活动序列` 中的一个数组项
- 活动数量不固定，可为 1 个、2 个、3 个或更多，按课程实际教学流程组织
- 不要因为前端示例标签展示了 `活动1`、`活动2`、`活动3` 就把活动数误判为固定 3 个

### 1.1 活动序列的生成口径
- `活动序列` 表示整次课程设计的阶段化教学流程，应按真实教学推进顺序组织
- 一个活动通常对应一个相对完整的教学阶段，例如：导入与目标明确、知识讲解、实验探究、案例分析、成果汇报、总结提升、课后拓展
- 当课程流程较短时，可以只有 1 个活动；当课程流程较复杂时，可以拆成多个活动
- 是否拆分为多个活动，应以教学意图、资源切换、地点变化、任务性质变化、时间结构变化为依据，而不是机械追求活动数量
- 每个活动下可以同时存在课上与课下时间，也可以只有其中一种
- 前端活动页签只是活动的展示容器，生成时应关注活动数组本身，而不是示例中的页签数量

### 1.2 活动基础信息的生成口径
- 每个活动至少要能稳定映射前端的 `活动号`、`活动名称`、`活动排序`
- `活动id` 是结构化唯一标识，用于数据层去重与定位，不等于前端展示文案
- 前端展示中的 `活动1`、`活动2`、`活动3` 更接近活动号或默认页签名；JSON 中仍应保留语义化 `活动名称`
- `排序` 用于驱动前端活动页签顺序与活动列表顺序，必须可直接排序
- 活动创建后可继续编辑活动详情，因此生成时应先把活动边界划分清楚，再补活动内部内容

### 1.3 活动知识建模图的生成口径
- 每个活动都可配置活动级 `知识建模图`
- 若已提供系统建模结果，优先保留 `系统建模编码`，并让 `文本` 与活动实际覆盖的知识点保持一致
- 若同时存在系统建模与上传图片，前端优先展示图片；生成时若无必要，不要同时堆叠两个来源造成歧义
- 活动级知识建模图应服务于活动目标生成，不要放与该活动无关的整课全量知识

### 1.4 活动目标的生成口径
- `活动目标` 对应单个活动下的目标列表，而不是整门课程总目标
- 若活动已有知识建模图，活动目标应优先从该活动知识建模图中抽取知识点、知识组块或稳定拆分项
- 活动目标应覆盖本活动实际出现的关键知识点，不要照搬全课程所有知识目标
- 活动目标中的 `学习水平` 允许多选；应根据该活动达成要求勾选 `记忆`、`理解`、`运用`
- 活动目标名称应尽量使用知识性表达或知识组块表达，不要改写成泛泛的口号句

### 1.5 活动导入任务的生成口径
- 活动级 `导入任务描述` 用于交代该活动如何唤醒先决知识并引出本次活动内容
- 第一个活动通常必须提供非空导入内容
- 后续活动若存在自然衔接、情境切换或任务过渡，也应提供导入内容
- 后续活动若前端允许留空且确实没有独立导入环节，可留空字符串或按前端约定处理；不要编造冗余导语
- 活动级导入内容应聚焦“如何引入”，不要把完整教学展开过程都写进导入字段
- 活动级 `师生交互过程` 若前端当前主要用于导入任务编辑，则应优先承载导入环节的师生互动过程
- `导入任务描述` 优先用短段落或时间线生成，只写唤起先决知识并引出新内容的互动
- `导入任务描述` 不要混入资源、学习成果、评价标准等其他字段信息
- `导入任务描述` 要出现教师引导语，并能自然把学生带到新内容
- 导入环节的 `师生交互过程` 优先按时间线式、多轮互动生成，每一轮尽量写清“教师：做什么 / 说什么”“学生：如何回应 / 讨论 / 输出什么”
- 导入环节应体现先决知识唤醒和内容引出的递进关系，避免只有一句空泛提问

### 2. 知识目标与活动目标都使用知识点对象数组
- `学习目标.知识目标` 是数组
- `活动目标` 是数组
- 每项都是 `{ 名称, 学习水平, 说明 }`
- `学习水平` 是数组，可从 `记忆`、`理解`、`运用` 中多选
- `学习水平` 至少选择 1 项，且不要重复
- `名称` 只写知识点或知识组块名称，不要把学习水平写进名称文本

### 2.1 知识目标的生成口径
- 优先提炼课程或活动中最关键的知识点、知识组块
- `学习目标.知识目标` 应优先覆盖整次课程设计的核心知识目标
- 若已知活动裁剪范围，知识目标应收敛到活动承载范围内的关键知识点及其目标学习水平组合
- `说明` 用于补充该知识点的掌握要求，可写“能解释……”“能区分……”“能用于……”

### 2.2 能力目标的生成口径
- `学习目标.能力目标` 是字符串数组，每项是一条可观察、可完成的能力表述
- 能力目标不要写成知识点名词，要写成“能够……”或等价的可执行能力表达
- 能力目标应尽量贴近任务完成、问题解决、分析判断、工具使用、协作沟通等专业能力
- 能力目标可参考前端示例中的三层粒度：
  - 最小能力：对应程序性知识点的运用水平，通常是一项技能
  - 中等能力：对应一个知识组块的运用水平，可完成一个较小任务
  - 综合能力：对应工作任务、子任务或任务模块
- 若课程内容较简单，至少给出与本次任务直接相关的 1 条能力目标；若内容较完整，优先覆盖由低到高的能力层次

### 2.3 素质目标的生成口径
- `学习目标.素质目标` 是字符串数组，每项是一条素质或价值导向表述
- 素质目标对应课程思政点、职业素养、科学精神、团队协作、责任意识等隐性目标
- 素质目标不要写成知识性结论，应该体现态度、意识、价值判断或行为倾向
- 素质目标应尽量与知识建模图、任务情境或专业场景相关联，不要写成脱离课程内容的空泛口号

### 2.4 学习先决知识的生成口径
- `学习先决知识` 是知识点对象数组，每项都是 `{ 名称, 学习水平, 说明 }`
- 字段结构与 `学习目标.知识目标` 一致，但语义上表示本次学习开始前学生已经需要具备的基础
- `学习先决知识` 应优先填写本次课程真正依赖的已有知识、前置概念、基础方法或基础操作能力
- 若提供了 `知识建模图`，`学习先决知识.名称` 应优先直接取自建模图中的知识点、知识组块或其稳定拆分项
- 不要为了补足数量凭空扩写先决知识；没有明确依赖关系的内容不要放进先决知识
- `学习水平` 表示学生在开课前应达到的已有水平，可按前端勾选多个层级
- `说明` 用于补充先决知识的最低掌握要求，可写“已能识别……”“已能完成……”“已能解释……”

### 2.5 学习先决知识与学习目标的区别
- `学习先决知识` 写“进入本次学习前已经需要会什么”
- `学习目标.知识目标` 写“完成本次学习后希望达到什么”
- 同一个知识点可以同时出现在两处，但学习水平和说明应体现“前置”与“目标”的区别
- 若某知识点已经作为先决知识包含 `运用`，通常不应再把它作为本次课程的核心新知识目标，除非课程是在更高复杂度场景下再次提升

### 3. 资源必须是对象数组
- `课上资源`、`课下资源`、活动资源、任务资源都用对象数组
- 每项至少包含：
  - `资源分类`
  - `资源描述`
- 可选补充：
  - `资源名称`
  - `链接`
  - `定位`
- 资源字段按条目拆分，不要合并成单个长字符串

### 3.1 教学资源的生成口径
- 顶层 `课上资源` 与 `课下资源` 对应前端“编辑教学资源”的两栏
- 资源应按用途或类别汇总后再填写 `资源分类`，例如：`任务工单`、`教材及参考书目`、`教学课件`、`学习中心`、`线上资源`、`测试题`
- `资源描述` 用于填写该分类下的具体资源内容，可写单项说明，也可按自然换行罗列同类条目
- 若某项资源有明确标题，可放入 `资源名称`；若前端当前只展示分类与描述，也仍需优先保证 `资源分类` 与 `资源描述` 可直接使用
- 课上资源优先放课堂讲授、演示、实验指导、任务工单、课件、板书提纲、课堂视频等
- 课下资源优先放学习中心资料、作业模板、测试题、拓展阅读、案例包、线上课程、外部链接等

### 3.2 教学资源的合并与去重规则
- 教学资源需要按活动资源分类汇总，不要把同类教材或同类资料拆成过多重复条目
- 同一教材、同一课件、同一资源如果在多个活动或任务中重复出现，顶层资源应优先合并成一条分类汇总描述
- 同一教材若引用了多个页码片段，可在 `定位` 中合并表达；若未单独使用 `定位`，可在 `资源描述` 中用顿号或分号清晰写出不同页码范围
- 合并后仍要保证可读性，不要把多个完全不同用途的资源粗暴拼成一段难以解析的长文本
- 没有真实资源支撑的分类不要硬造；资源分类名称应尽量稳定、可复用、便于前端展示

### 4. 富文本字段用内容块数组
- `师生交互过程`
- `学习成果`
- `评价标准`

以上字段都使用数组，元素为：

```json
{ "类型": "文本", "内容": "..." }
```

或：

```json
{ "类型": "图片", "地址": "..." }
```

### 4.1 适合按富文本区域生成的字段
- 以下字段在内容组织上都应按富文本思路生成，而不是短句、标签或碎片化词组：
  - `知识组块`
  - 活动级 `导入任务描述`
  - `师生交互过程`
  - `学习成果`
  - `评价标准`
  - `备注`
- 其中只有 `师生交互过程`、`学习成果`、`评价标准` 在 schema 中是富文本内容块数组
- `知识组块` 在 schema 中仍是字符串数组，但每项内容可按多行、树状、层级化文本表达，不要退化成简单名词列表
- 活动级 `导入任务描述`、`备注` 在 schema 中仍是普通字符串字段，只是在内容组织上按富文本思路生成

### 4.2 富文本区域通用生成原则
- 优先生成有层次、有递进、有关系词的完整内容，不要只堆关键词
- 能分段时分段，能分轮次时分轮次，能体现因果、并列、包含、前提关系时要明确写出
- 避免口号式、标题式、标签式内容
- 富文本内容要与所在字段职责一致，不要跨字段混写

### 5. 建模图字段要保留结构化引用
- 顶层、活动级、任务级都可有 `知识建模图`
- 结构固定为：

```json
{
  "系统建模编码": "",
  "文本": "",
  "图片列表": []
}
```

其中：
- `系统建模编码` 用于对接前端已有建模选择能力
- `文本` 用于 LLM 直接生成的知识结构表达
- `图片列表` 用于承接上传图片或外部图片

### 6. 任务结构必须完整

每个任务必须包含：
- `任务id`
- `排序`
- `任务名称`
- `知识建模图`
- `知识组块`
- `任务描述`
- `任务时长分钟`
- `学习地点`
- `教学方式`
- `师生交互过程`
- `学习成果`
- `评价标准`
- `学习资源`
- `上传资源`
- `备注`

### 6.1 任务基础信息的生成口径
- 每个活动下的 `任务序列` 是数组，任务数量不固定，可按活动内部实施步骤继续拆分
- 每个任务至少要能稳定映射前端的 `任务号`、`任务名称`、`任务排序`
- `任务id` 是结构化唯一标识，用于数据层定位与去重，不等于前端展示文案
- 前端中的 `任务一`、`任务二` 更接近任务号或默认页签名；JSON 中仍应保留语义化 `任务名称`
- `排序` 用于驱动同一活动内的任务执行顺序，应与前端任务列表顺序一致

### 6.2 任务知识建模图与知识组块
- 每个任务都可配置任务级 `知识建模图`
- 任务级 `知识建模图` 应只覆盖该任务实际处理的知识点，不要照搬整个活动的全量建模
- `知识组块` 应与任务级 `知识建模图`、`任务描述`、`学习成果` 保持一致
- `知识组块` 用于列出该任务直接处理的知识点、知识模块或稳定的知识拆分项
- 若任务级建模图已给出明确知识点，`知识组块` 应优先复用建模图中的命名
- `知识组块` 的内容表达优先按树状、多行结构生成，要体现层级和关系，而不是简单平铺列表
- `知识组块` 应尽量保留知识关系词，如：`支持`、`具有特征`、`内容包含`、`步骤包含`、`是前提`等建模图中关系
- 若是活动级知识裁剪到任务级，`知识组块` 应是活动知识范围内的进一步子集，不要反向扩张到其他活动内容

### 6.3 任务描述的生成口径
- `任务描述` 是任务级核心字段，应用一句或几句完整表述交代“因为什么思考或原因，采用什么教学策略，达到什么学习结果”
- `任务描述` 应体现任务意图、实施策略与预期学习结果，不要只写主题名词
- `任务描述` 应与 `知识组块` 保持一致，不能出现知识组块之外的核心知识目标漂移
- `任务描述` 应与 `教学方式`、`师生交互过程` 保持一致，避免描述中说讨论，方式中却没有讨论

### 6.4 任务时长与学习地点
- `任务时长分钟` 使用整数分钟
- 任务时长应结合师生交互行为与资源使用情况合理预估，通常按大多数学生实际完成的平均时长估算
- `学习地点` 只能在 `课上`、`课下` 中二选一
- 若同一学习任务跨越课上与课下，应拆成两个任务分别描述

### 6.5 任务教学方式的生成口径
- `教学方式` 对应前端“教学方式（或学习方式）”勾选区
- `教学方式.方式` 允许多选，但至少选择 1 项，且应与 `任务描述` 中的教学策略一致
- 前端当前可选项按以下口径对齐：`讲授`、`小组讨论`、`答疑`、`实验`、`实训`、`自主学习`、`翻转课堂`、`其他`
- 当 `教学方式.方式` 包含 `其他` 时，`教学方式.其他` 应写明具体方式；否则保持空字符串
- 若 `学习地点` 为 `课下`，应优先使用 `自主学习`、`翻转课堂` 或明确填写的 `其他` 方式

### 6.6 任务师生交互过程
- `师生交互过程` 应体现任务实施过程，不需要把课堂上的每一句对话都写出来
- 优先按时间线式、多轮互动生成，每一轮都尽量写：
  - 教师：做什么 / 说什么
  - 学生：如何回应 / 操作 / 讨论 / 输出什么
- 内容应围绕教师如何组织、学生如何参与、教师如何追问或反馈、任务如何推进来描述
- `师生交互过程` 应与 `任务描述`、`教学方式` 保持一致
- 要体现教学策略是如何落地的，不要只写“采用讨论法”“采用案例法”这类策略名称
- 教师行为必须具体可操作，学生行为必须具体可观察
- 避免空泛问答，尽量设计有递进的引导问题、操作步骤或反馈节点
- 若任务主要为课下自主完成，也要写交互，但重点放在任务布置、资源说明、答疑、提交要求、教师反馈机制等关键过程

### 6.7 任务学习成果与评价标准
- `学习成果` 必须有，且应与任务描述中的学习目标一致，要求可呈现、可观察、可测评
- 常见学习成果可以是文本、报告、表格、实物模型、视频、音频、产品、课堂笔记、课堂作业、学生行为表现等
- `评价标准` 必须与 `学习成果` 一一对应或整体匹配，说明如何判定成果是否达标
- 不要把“学习成果”和“评价标准”合并成同一段内容
- 富文本内部建议固定成三段：
  - `学习成果：`
  - `评价标准：`
  - `评价方式：`
- `学习成果` 优先写成具体产物或具体表现，如表格、报告、微词条、练习结果、口头阐述、操作记录、作品或任务提交物
- `评价标准` 优先分层表达，如 `优秀(A)`、`良好(B)`、`合格(C)`、`待改进(D)`
- `评价方式` 用于补充评价采用的方式，如教师评价、同伴互评、课堂观察、测试计分、作品评分、提交审核等
- 若 `学习水平` 偏 `记忆`，学习成果可偏向小测、口头回答、知识点辨识
- 如果目标里包含 `记忆` 层次知识点，学习成果应优先生成测试题形式，例如选择题、填空题、判断题
- 记忆层次的测试题应尽量标明正确答案、分值
- 记忆层次任务的评价标准优先采用客观得分
- 若 `学习水平` 偏 `理解`，学习成果可偏向阐述、比较、解释、分类
- 若 `学习水平` 偏 `运用`，学习成果可偏向任务操作、产品产出、方案设计、案例处理

### 6.8 任务学习资源与上传资源
- `学习资源` 对应资源描述类条目，应与任务学习目标匹配
- `学习资源` 的每一项仍使用 `资源分类`、`资源描述` 为核心字段，可补充 `资源名称`、`链接`、`定位`
- `学习资源` 应只放教学中引用、分发、阅读、使用的资源说明
- `上传资源` 对应文件上传类条目，单独存放附件信息，不要混入 `学习资源`
- 若前端当前任务资源分为“资源描述”和“资源上传”两个页签，JSON 中应保持这两类数据分离

### 6.9 任务备注
- `备注` 用于补充难以归入其他字段、但对任务执行或理解有帮助的信息
- `备注` 不是重复填写 `任务描述`、`师生交互过程` 或 `评价标准` 的备用字段
- `备注` 不是空泛总结，应优先写对后续教学有指导意义的信息
- 默认应尽量生成有信息量的备注，例如课堂表现特征、常见问题、提交要求、分组要求、工具提醒、易错点、教师观察重点等
- 备注可优先写：
  - 学生普遍卡在哪
  - 哪类学生要重点关注
  - 哪种引导语或活动有效
  - 下次如何调整
- 只有在确实没有额外补充信息时，才留空字符串

### 7. 教学方式结构

固定结构：

```json
{
  "方式": ["讲授", "小组讨论"],
  "其他": ""
}
```

`方式` 可选值仅限：
- `讲授`
- `小组讨论`
- `答疑`
- `实验`
- `实训`
- `自主学习`
- `翻转课堂`
- `其他`

### 8. 时间统一用整数分钟
- 使用 `课上分钟`、`课下分钟`、`任务时长分钟`
- 不要写成 `"15分钟"`

### 8.1 课上与课下时间分配的生成口径
- `课程信息.学时安排` 对应前端“编辑课上与课下时间分配”的两个输入框
- `课程信息.学时安排.课上分钟` 表示整次课程设计的全部课上时间总和
- `课程信息.学时安排.课下分钟` 表示整次课程设计的全部课下时间总和
- 活动级 `时间分配` 表示该活动内部的课上/课下时间汇总
- 任务级只填写 `任务时长分钟` 与 `学习地点`，不再单独拆出任务级 `课上分钟`、`课下分钟`
- 生成时应先确定任务级时长与学习地点，再汇总得到活动级 `时间分配`，最后汇总得到课程级 `学时安排`

### 8.2 时间分配的拆分原则
- 每个任务只能属于一种 `学习地点`：`课上` 或 `课下`
- 课上任务通常包括讲授、讨论、实验、答疑、展示、课堂训练等
- 课下任务通常包括预习、自主学习、课后练习、资料阅读、线上学习、作业完成、项目延伸等
- 若任务发生在课堂内外结合场景，应拆成两个任务分别建模，而不是在同一任务里混写课上和课下时间
- 时间分配应尽量贴近真实教学节奏，避免出现大量 1 分钟、2 分钟这类不自然切分
- 若课程有固定学时，如 45、90、100、120 分钟，应优先让任务拆分符合常见教学组织节奏

## 前端适配约束

这套 JSON 需要能顺滑映射到前端当前导入/保存逻辑，因此生成时必须满足：

- 顶层 `课上资源`、`课下资源` 可直接映射为课程资源明细
- 活动级 `课上资源`、`课下资源` 可直接映射为活动序列表汇总资源
- `活动序列` 需保持可扩展数组结构，前端活动标签数量应由数组项数量自然决定，不预设上限为 3
- 活动对象中的 `活动名称`、`排序`、`活动目标`、`知识建模图`、`导入任务描述`、`时间分配`、`课上资源`、`课下资源` 应能分别映射活动详情页对应板块
- 任务对象中的 `任务名称`、`排序`、`知识建模图`、`知识组块`、`任务描述`、`任务时长分钟`、`学习地点`、`教学方式`、`师生交互过程`、`学习资源`、`上传资源`、`学习成果`、`评价标准`、`备注` 应能分别映射任务详情页对应板块
- 顶层教学资源应按分类汇总展示，避免同一教材、课件或资料在前端形成多条重复记录
- `资源分类` 应可直接作为前端分类标题，`资源描述` 应可直接作为分类内容展示
- `课程信息.学时安排` 需保持 `{ 课上分钟, 课下分钟 }` 的整数结构，便于映射时间分配编辑器
- 活动级 `时间分配` 需保持 `{ 课上分钟, 课下分钟 }` 的整数结构，便于前端活动汇总展示
- `活动目标` 可直接映射为前端 `pointList / pointSummaryList`
- `学习目标.知识目标` 需保持 `名称 + 学习水平 + 说明` 的知识点对象结构，便于映射知识点目标编辑器
- `学习目标.能力目标` 需保持纯字符串数组，便于映射能力目标逐条输入框
- `学习目标.素质目标` 需保持纯字符串数组，便于映射素质目标逐条输入框
- `学习先决知识` 需保持 `名称 + 学习水平 + 说明` 的知识点对象结构，便于映射学习先决知识编辑器
- `学习目标.知识目标`、`活动目标`、`学习先决知识` 中的 `学习水平` 需允许多选、至少选择 1 项，并保持数组结构
- 若前端存在“从建模图中选择”，则 `学习先决知识` 与 `学习目标.知识目标` 的名称应优先使用建模图内已有知识点名称
- `教学方式.方式` 使用中文标签，允许多选且至少选择 1 项，前端再做字典映射
- `师生交互过程`、`学习成果`、`评价标准` 需能承接富文本编辑器内容，并保持三者语义分工清晰
- `学习成果` 与 `评价标准` 分开，不要合并成一个字段
- `上传资源` 单独存，不要混进 `学习资源`
- 活动级 `导入任务描述` 与 `师生交互过程` 分开
- `备注` 默认尽量生成，不要机械统一写空字符串

## 业务约束

- 活动对象中的 `排序` 必须与 `活动序列` 的数组顺序一致，从 1 开始连续递增
- 任务对象中的 `排序` 必须与 `任务序列` 的数组顺序一致，从 1 开始连续递增
- 同一文件内 `活动id` 不得重复
- 同一文件内 `任务id` 不得重复
- 每个活动的 `时间分配` 必须等于其下任务按 `学习地点` 汇总后的分钟数
- `课程信息.学时安排` 必须等于所有活动的时间分配汇总
- 知识点、活动目标、任务、资源、学习成果、评价标准、时间分配之间必须相互对应，不能各写各的
- 若 `学习地点` 为 `课上`，`教学方式.方式` 不能包含 `自主学习`
- 若 `学习地点` 为 `课下`，`教学方式.方式` 不能包含 `讲授`
- 若 `课程类型` 包含 `项目化`，通常必须提供非空 `能力目标`

## 生成建议

- `活动名称` 使用真实语义名称
- `活动序列` 先按教学阶段拆分，再为每个阶段组织目标、时间与资源；不要默认只生成 3 个活动
- 先确定每个活动的名称、排序和覆盖知识范围，再填写活动目标、导入任务、时间与资源
- 第一个活动优先承担课程导入、目标明确或先决知识唤醒功能；后续活动再承接讲解、训练、总结或拓展
- `任务名称` 使用语义化名称
- 先确定任务级知识点与任务意图，再填写 `任务描述`、`教学方式`、`师生交互过程`、`学习成果` 与 `评价标准`
- `知识组块`、`导入任务描述`、`师生交互过程`、`学习成果`、`评价标准`、`备注` 默认按富文本区域思路生成，不要退化成短句或标签
- `师生交互过程` 默认按时间线式、多轮互动生成，优先写清教师动作、学生回应、引导递进和输出结果
- `学习成果`、`评价标准` 默认优先按“学习成果 / 评价标准 / 评价方式”三段组织
- `学习成果` 先写学生最终要呈现什么，再反推 `评价标准` 如何判断达标
- `学习资源` 只写任务中真实使用的资源，`上传资源` 只写附件型文件
- `备注` 优先补充执行提醒、观察重点、提交要求、易错点、课堂组织信息或后续调整建议，不要默认留空
- 若提供了总知识建模图，先按总图确定核心知识，再裁剪到活动、再细化到任务
- 核心知识点、难点、易错点优先安排在课上，由教师进行引导、讲解、讨论或示范
- `知识目标` 先抽取知识点，再为每个知识点判断应勾选的一个或多个学习水平
- `能力目标` 优先写成可直接观察的行动表达，如“能够分析……”“能够完成……”“能够使用……”
- `素质目标` 优先结合课程思政、职业规范、科学精神、团队协作等真实场景表述
- `学习先决知识` 优先提取本次课程真正依赖的前置知识点，并尽量复用知识建模图中的原始命名
- `课上资源`、`课下资源` 先按分类归并，再补充分项描述，不要把每个文件都机械拆成独立分类
- 先确定每个任务的 `学习地点` 与 `任务时长分钟`，再反推活动级和课程级的课上/课下时间分配
- `知识组块` 用字符串数组表达知识点或知识模块
- `导入任务描述` 聚焦引入情境，不要和 `师生交互过程` 混写
- `资源描述` 要写清楚资源用途，不要只写资源名
