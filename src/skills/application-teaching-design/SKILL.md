# 课程设计 JSON 结果文件生成

## 任务目标

你的目标不是解释思路，而是**直接产出最终课程设计 JSON**。

默认交付物必须满足：
- 可直接保存为 JSON 文件
- 根结构与 `references/demo.json` 一致
- 中文字段名稳定，不擅自改名
- 内容覆盖学习目标、学习先决知识、资源、时间、活动序列、活动详情、任务详情、学习成果及评价标准、备注

如果用户只说“帮我生成教学设计 / 课程设计 / 教案 JSON / 按 demo.json 输出”，直接按本技能执行。

## 何时触发

遇到以下场景应使用本技能：
- 用户要“生成课程设计 JSON”“输出教学设计结果文件”“按固定 JSON 结构生成教案”
- 用户给出课程名称、学时、专业、任务内容，希望你补全完整教学设计
- 用户给出知识建模图 JSON，希望据此生成教学设计其余部分
- 用户要求输出类似 `demo.json` 的课程设计最终结果
- 用户明确要求产出可落库、可存档、可交付的教学设计结构化数据

以下情况不要停留在自然语言：
- 只给大纲
- 只给 Markdown 教案
- 只给局部字段
- 只解释怎么设计

## 先收集信息

### 必填信息
若缺失，先追问：
- 课程名称
- 课程设计名称 / 教案名称 / 周次课次
- 学时安排（需明确课上 / 课下）
- 课程类型
- 教学形式
- 适用专业
- 学生层次
- 任务内容

### 选填信息
有就吸收，没有也要继续生成：
- 知识建模图 JSON
- 教材页码、课件、讲义、案例、题库、作业模板
- 评价重点
- 课程思政点
- 教学资源清单
- 用户提供的结果样例

优先建议用户提供**知识建模参考文件**（如知识建模图 JSON 或能体现知识点关系的结构化材料），因为这最有利于把核心知识点、先决知识、活动目标与学习目标准确关联起来，从而提升课程设计 JSON 的一致性。

## 输入资料使用原则

### 用户资料是增强项，不是唯一前提
- 有资料：提炼并吸收有效信息
- 无资料：仍依据课程名称、学时、任务内容、专业背景独立生成

### 若提供知识建模图 JSON
重点读取：
- `nodes`：识别知识点、案例、先决知识、思政点
- `lines`：识别关系，至少理解 `from`、`to`、`text`

常见关系包括：
- `支持`
- `具有特征`
- `内容包含`
- `步骤包含`
- `是前提`
- `关键点包含`

常见映射方式：
- 核心知识点 → 学习目标 / 活动目标
- 先决知识 → 学习先决知识 / 导入任务
- 步骤或流程 → 活动切分 / 任务序列 / 能力目标
- 案例与素材 → 学习资源
- 思政点 → 素质目标（课程思政点）

不要为了“解释建模图”而偏离最终交付物；你要做的是把它转化为课程设计 JSON 中需要的目标、活动、任务与资源。

### 固定字段中的“知识建模图”
结果 JSON 中必须保留 `知识建模图` 字段，因为它是 `demo.json` 的固定结构之一。

规则：
- 优先建议选择系统知识建模或知识建模参考文件，以便更好关联学习目标、活动目标、先决知识与思政点
- 若用户提供了相关图片 / 图示，可放入 `images`
- 若系统建模与上传图片同时存在，通常以图片作为展示优先项；若需要突出系统建模，应避免让上传图片覆盖其展示语义
- 若没有图，按占位结构保留：

```json
{
  "key": "知识建模图",
  "value": "知识建模图：\n",
  "images": []
}
```

## 课程类型适配

### 两类课程
- 第一类：应用型研究方向项目化教学课程 / 专业基础课程 / 公共基础课程
- 第二类：就业方向项目化教学课程

### 学习目标差异
- 第一类课程：`知识点（学习水平）` + `素质目标（课程思政点）`
- 第二类课程：`知识点（学习水平）` + `能力目标` + `素质目标（课程思政点）`

### 学科表达适配
- 理工类：公式用 LaTeX，特殊符号用 Unicode
- 文史类：强调规范表达、阅读材料、讨论与写作任务
- 政治类：坚持正确价值导向，避免不当敏感表述
- 艺术类：可加入图像、案例、素材等多模态资源

## 输出结构要求

最终输出必须是一个完整 JSON 对象：

```json
{
  "标题": "课程标题",
  "课程设计名称": "课程设计名称",
  "课程设计": [],
  "活动序列": {}
}
```

格式约束要求：
- 输出结果必须同时对齐 `references/demo.json` 的字段风格与 `references/schema.json` 的结构约束
- `demo.json` 用于理解字段组织与内容风格，`schema.json` 用于最终结构校验

校验方式：
- 默认校验示例文件：`python3 src/skills/application-teaching-design/scripts/validate_json.py`
- 校验指定结果文件：`python3 src/skills/application-teaching-design/scripts/validate_json.py path/to/result.json`

### `课程设计` 数组必须按顺序包含 8 个板块
1. `学习目标`
2. `学习先决知识`
3. `知识建模图`
4. `课上资源`
5. `课下资源`
6. `课上时间`
7. `课下时间`
8. `活动序列`

### 根层 `活动序列` 必须展开活动详情
每个活动下至少包含：
- `知识建模图`
- `活动任务序列（导入任务描述）`
- `活动目标`
- `师生交互过程`
- `活动任务序列（任务）`

### 每个任务对象至少包含
- `任务名称`
- `知识组块`
- `任务描述`
- `任务时长`
- `学习地点`
- `教学方式（或学习方式）`
- `师生交互过程`
- `学习资源`
- `学习成果及评价标准`
- `备注`

兼容说明：
- `references/demo.json` 中有少量任务缺少 `教学方式（或学习方式）`，因此 `references/schema.json` 对该字段按“可选但推荐补全”处理
- 新生成结果仍应优先补全 `教学方式（或学习方式）`，不要沿用样例中的缺口

## 字段类型速查（以 `references/demo.json` 为准）

### 根层字段
- `标题`: 字符串
- `课程设计名称`: 字符串
- `课程设计`: 数组
- `活动序列`: 对象

### `课程设计` 数组中的 8 个板块
- `学习目标`: 对象，结构为 `{ "key": "学习目标", "value": { ... } }`
- `学习先决知识`: 对象，结构为 `{ "key": "学习先决知识", "value": { ... } }`
- `知识建模图`: 对象，结构为 `{ "key": "知识建模图", "value": "字符串", "images": [] }`
- `课上资源`: 对象，结构为 `{ "key": "课上资源", "value": "字符串" }`
- `课下资源`: 对象，结构为 `{ "key": "课下资源", "value": "字符串" }`
- `课上时间`: 对象，结构为 `{ "key": "课上时间", "value": "100分钟" }`
- `课下时间`: 对象，结构为 `{ "key": "课下时间", "value": "220分钟" }`
- `活动序列`: 对象，结构为 `{ "key": "活动序列", "value": { ... }, "sorted_names": [] }`

### `学习目标.value` 字段
- `知识点（学习水平）`: 字符串
- `素质目标（课程思政点）`: 字符串
- `能力目标`: 条件字段，仅特定课程类型需要；如出现，类型为字符串

### `学习先决知识.value` 字段
- `知识点（学习水平）`: 字符串

### `课程设计[].活动序列.value` 字段
- 每个活动名称对应一个数组，例如 `"活动1": [ ... ]`
- 同一活动下可以出现多条记录，这些记录既可以表示同一活动目标在 `课上` / `课下` 的拆分，也可以表示同一活动下的多个不同活动目标
- 不要把一个活动下的所有活动目标强行合并成单条记录；应按“一个活动目标一条或两条记录（课上 / 课下）”组织
- 数组中的每条记录都是对象，包含：
- `活动目标`: 字符串
- `地点`: 字符串
- `时间`: 字符串
- `学习资源`: 字符串
- `课程设计[].活动序列.sorted_names`: 数组，元素为活动名称字符串，顺序必须与 `value` 中活动顺序一致

### 根层 `活动序列` 下的每个活动对象
- `知识建模图`: 对象，结构为 `{ "key": "知识建模图", "value": "字符串", "images": [] }`
- `活动任务序列（导入任务描述）`: 字符串
- `活动目标`: 字符串，用于汇总表达该活动下的全部活动目标；当存在多个活动目标时，应按 `；` 等分隔方式完整列出，不要只保留一个
- `师生交互过程`: 字符串
- `活动任务序列（任务）`: 数组

### `活动任务序列（任务）` 中每个任务对象
- `任务名称`: 字符串
- `知识组块`: 对象，结构为 `{ "key": "知识组块", "value": "字符串", "images": [] }`
- `任务描述`: 字符串
- `任务时长`: 字符串
- `学习地点`: 字符串
- `教学方式（或学习方式）`: 对象，结构为 `{ "key": "...", "value": "字符串", "checkbox": [[], []], "checkbox_other": "字符串" }`
- `师生交互过程`: 对象，结构为 `{ "key": "师生交互过程", "value": [], "images": [] }`
- `学习资源`: 字符串
- `学习成果及评价标准`: 对象，结构为 `{ "key": "学习成果及评价标准", "value": [], "images": [] }`
- `备注`: 字符串

## 总体生成原则

1. 先保证**结构完整**，再优化内容质量。
2. 学习目标、活动目标、任务内容、资源、评价标准必须相互对应。
3. 活动切分要合理，能支撑课堂推进与课下延伸。
4. 课上与课下时间总和要与活动明细一致。
5. 课上资源、课下资源、教学资源、活动序列表、时间分配均优先通过汇总逻辑生成，不要重复手工改写。
6. 师生交互过程要具体到同专业教师可直接参考上课。
7. 评价标准要可执行、可观察、可判定。
8. 缺失项可用 `""`、`/`、空数组等占位，但不能破坏结构。
9. 输出优先服务结果交付，不要夹杂长篇解释。

## 学习目标与学习先决知识

### 统一学习水平 tag
以下内容都支持标注 1 个或多个 tag，且 tag 只允许使用：
- `记忆`
- `理解`
- `运用`

适用范围：
- `知识点目标（学习水平）`
- `能力目标`
- `素质目标（课程思政点）`
- `学习先决知识`

### 知识点目标（学习水平）
用于表达**总活动目标**，对应 demo.json 中的 `知识点（学习水平）` 字段。

规则：
- 需结合活动裁剪结果，优先确定该活动的**最高阶知识点目标**
- 优先写能代表该活动核心价值的知识点，而不是机械罗列所有知识点
- 知识点既可以是理论概念，也可以是专业任务型、方法型、分析型知识点
- 每个知识点可标注 1 个或多个学习水平 tag
- 与活动目标保持一致

**格式要求（对齐 demo.json）**：
- 使用编号列表格式
- 每个知识点后用中文括号标注学习水平
- 多个 tag 用`、`分隔

推荐写法示例：

```text
知识点目标（学习水平）
1. 知识点1（理解、记忆）
2. 知识点2（记忆）
3. 知识点3（记忆、理解、运用）
```

### 能力目标
仅第二类课程（就业方向项目化教学课程）需要。

对应 demo.json 中 `学习目标.value.能力目标` 字段。

能力目标用于表达**学生应具备的专业能力**，按 3 个层次生成：
1. 最小能力层：对应程序性知识点的`运用`学习水平，通常表现为某项具体技能
2. 知识组块层：对应一个知识组块的`运用`水平，能够完成一个较小任务
3. 工作任务层：对应一项工作任务、子任务或任务模块，体现较完整的职业任务能力

规则：
- 要和课程内容、活动裁剪、任务设计保持一致
- 本质上是学生应具备的专业能力，而不是泛泛的学习愿望
- 尽量落到可执行、可观察、可评价的行为上
- 优先使用“能够……”句式
- 尽量放入明确的工作任务情境中，不只写抽象能力名词

常见写法例如：
- 能够独立完成××技能操作
- 能够基于××知识组块完成小型任务
- 能够进行××分析
- 能够识别和确定××定位与价值
- 能够根据任务工单独立完成××任务
- 能够制定××实施方案
- 能够执行××流程
- 能够完成××效果评测
- 能够识别并解决××常见问题

### 素质目标（课程思政点）
规则：
- 与课程内容紧密相关
- 与具体教学活动有落点
- 思政点（隐性知识）需要与知识建模图对应
- 不要只写空泛口号，应尽量体现专业视角、思维品质、职业素养或责任意识
- 尽量与具体专业内容或任务情境绑定
- 有明确思政点时用 `*` 标注
- 没有可填 `/`

### 学习先决知识
对应 demo.json 中 `学习先决知识.value.知识点（学习水平）` 字段。

规则：
- 写完成本次学习前必须具备的基础知识
- 应围绕**总活动目标**确定，并结合活动裁剪结果反推出支撑该活动的前置知识
- 尽量完整罗列，而不是只写少量笼统概念
- 内容既可以是理论知识，也可以是方法、分析模型、工具操作、业务认知与已有技能基础
- 直接服务导入任务与后续活动展开

**格式要求（对齐 demo.json）**：
- 使用分号 `；` 分隔多个知识点
- 每个知识点后用中文括号标注学习水平

示例：
```text
定时器（理解）；能够完成定时的器件（理解）；可调节定时时间（理解）；计数器（理解）；能够完成脉冲计数的器件（理解）；可以加计数或减计数（理解）
```

## 资源与时间汇总规则

### 教学资源 / 课上资源 / 课下资源
规则：
- `教学资源`、`课上资源`、`课下资源` 都应从包含的子项资源中汇总生成，而不是独立凭空编写
- 完成每个任务下的资源编辑后，应通过汇总逻辑自动汇总各任务资源
- 先按任务收集资源，再按课上 / 课下拆分，再按资源类别分类汇总
- 教学资源整体上通常按“课上资源 / 课下资源 → 资源分类 → 资源描述”组织
- 活动序列表中的 `学习资源` 也应优先基于活动资源汇总结果自动带出

资源整理要求：
- 资源分类是必填项
- 资源描述应尽量具体说明该分类下的资源内容
- 出现重复教材、课件、平台、视频、工具等资源时，应合并去重
- 同一教材如果出现多次但页码不同，应合并为一条，并用 `、` 连接页码
- 学习资源应匹配学习目标

资源类型建议至少考虑：
- 教材及参考书
- 案例
- 课件 / 学习中心资源
- 上传附件
- 线上资源

格式要求：
- 教材及参考书尽量采用规范引文格式
- 案例需说明主题及关键构成
- 课件 / 学习中心资源名称应与知识模块保持一致
- 线上资源尽量给出完整链接与资源说明

示例：
`盛骤，谢式千，潘承毅.概率论与数理统计[M].第五版，高等教育出版社.2019.12，P91-92、P93-101。`

### 课上时间 / 课下时间
规则：
- `课上时间` 与 `课下时间` 都是必填项，统一使用“分钟”
- 完成每个活动及活动下任务编辑后，应通过汇总逻辑自动生成课上与课下时间分配，而不是随意手填总量
- `课上时间` 应与所有课上活动 / 任务时间汇总结果一致
- `课下时间` 应与所有课下活动 / 任务时间汇总结果一致
- 活动序列表中的 `时间` 应与对应活动下课上 / 课下时间汇总结果一致

## 活动层规则

### 活动序列（课程设计数组中的板块）
规则：
- 活动序列表不是独立凭空编写的，而是完成每个活动及活动下任务编辑后，通过汇总逻辑自动生成部分内容
- 活动应先确定编号、名称与排序，再展开活动详情
- 活动排序是刚性字段，必须与 `sorted_names` 和最终活动顺序保持一致
- 活动名称应体现该活动的主题、阶段或核心任务，不宜使用空泛占位名称
- 每个活动可以包含多个活动目标；每个活动目标通常再拆成 `课上` / `课下` 两条记录
- 活动序列表中每条记录都应包含：`活动目标`、`地点`、`时间`、`学习资源`
- 其中 `活动目标`、`时间`、`学习资源` 应优先从活动详情、任务明细与资源汇总中自动汇总生成
- `地点` 按 `课上` / `课下` 拆分，同一活动目标通常对应一条课上记录和一条课下记录；若某活动下有多个活动目标，则应生成多组记录
- 使用 `sorted_names` 标明活动顺序
- 生成流程上应先建立活动骨架，再补活动目标、导入任务、师生交互与任务明细，最后汇总形成活动序列表
- 一个活动下允许出现多个不同的 `活动目标` 值；只要它们都属于该活动并与知识建模图一致，就不要压缩成单个总目标

### 活动目标
规则：
- 列出该活动知识建模图中出现的全部知识点，但排除绿色先决知识
- 按 `知识点（学习水平）` 撰写
- 每个知识点都要匹配学习水平；若同一知识点涉及多个层次，按 `记忆 < 理解 < 运用` 取最高级别作为该活动目标展示
- 与总学习目标保持一致
- 支持从建模图中单个选择或批量选择，优先确保与知识建模图完全对齐
- 如果同一活动下存在多个相对独立的知识点目标，应拆成多个活动目标项，而不是简单拼成一句笼统描述
- 在 `课程设计[].活动序列.value.活动X` 中，应让每条记录的 `活动目标` 保持单一、清晰、可直接映射到前端一个输入框
- 在根层 `活动序列.活动X.活动目标` 中，则对这些活动目标项做完整汇总，确保不遗漏

### 导入任务描述
规则：
- 围绕先决知识唤醒设计，目标是引出本次课程内容
- 第一个活动的导入任务必须写；后续活动之间如有衔接则写，没有则写 `/`，不要留空
- 导入应尽量采用真实、具体、可感知的场景切入，而不是空洞提问
- 导入结构建议形成“情境切入 → 教师提问 → 学生回应 → 教师顺着学生思路总结并引出新课”的闭环
- 教师总结部分应承担承上启下作用，明确把学生回答提升到本次课主题
- 时长一般控制在 5 分钟左右

推荐格式：

```text
教师：展示具体场景 / 案例 / PPT 画面，引导学生进入问题情境。
学生：结合已有经验回忆、观察并回答。
教师：追问、比较、提炼学生观点，挖掘现象背后的关键因素。
学生：补充、讨论、形成初步判断。
教师：顺着学生思路总结，并明确指出“本节课就从……入手”。
教学策略：经验连接法、问题引导法、情境创设法
```

## 任务层规则

### 任务名称与层级
规则：
- 一个活动下可以包含多个任务，任务必须从属于某个活动
- 任务名称应体现具体任务内容，不要只写笼统占位词
- 生成流程上应先建立活动—任务层级骨架，再补全任务描述、时长、地点、教学方式、资源、评价与备注

### 知识组块
对应 demo.json 中每个任务的 `知识组块` 字段，是**对象结构**：

```json
{
  "key": "知识组块",
  "value": "任务一知识组块：\n",
  "images": []
}
```

规则：
- 每个任务都必须有知识组块
- 知识组块与任务一一对应
- 可用占位结构，也可填写具体知识内容
- 任务应按教学推进逻辑拆分成若干可执行单元，知识组块也要与这种拆分粒度一致

### 任务描述
按这个逻辑写：

> 因为何种教学思考或学习难点，采用什么教学策略，达到什么学习结果。

补充要求：
- 建议遵循“背景 / 动因 + 教学策略 + 学习结果”的完整逻辑链
- 学习结果必须与所属知识组块中的知识点保持一致
- 若引用教学理论或认知框架，可明确写出其支撑作用

### 任务时长
规则：
- 必须结合具体的师生交互行为与教学资源进行合理预估
- 建议以 80% 及以上学生实际完成该任务的平均时长作为估算依据
- 统一使用“分钟”

### 学习地点
规则：
- 一个任务只对应一种地点：`课上` 或 `课下`
- 学习地点具有唯一性，不可同时填写课上和课下

### 教学方式（或学习方式）
对应 demo.json 中每个任务的 `教学方式（或学习方式）` 字段，是**对象结构**，必须保留完整结构：

```json
{
  "key": "教学方式（或学习方式）",
  "value": "讲授   小组讨论   答疑   实验   实训   自主学习   翻转课堂   其他（请填写）__xxx___",
  "checkbox": [
    ["讲授", "小组讨论", "答疑", "实验", "实训", "自主学习", "翻转课堂", "其他（请填写）"],
    [0, 2]
  ],
  "checkbox_other": "xxx"
}
```

固定选项通常包括：
- 讲授
- 小组讨论
- 答疑
- 实验
- 实训
- 自主学习
- 翻转课堂
- 其他（请填写）

规则：
- `checkbox[0]` 为固定选项列表
- `checkbox[1]` 为被选中的索引数组
- 若有补充方式，写入 `checkbox_other`
- 教学方式必须与任务描述中的教学策略、教学方法保持一致
- 若选择 `自主学习`，学习地点必须为 `课下`
- 若选择 `其他`，填写内容应使用规范的教育教学术语

### 学习资源（任务级）
规则：
- 单个任务中的学习资源建议至少考虑：教材及参考书、案例、课件 / 学习中心资源、上传附件、线上资源等几类
- 教材及参考书尽量采用规范引文格式
- 案例需说明主题及关键构成
- 课件 / 学习中心资源名称应与知识模块保持一致
- 线上资源尽量给出完整链接与资源说明
- 任务级资源是上层 `教学资源 / 课上资源 / 课下资源 / 活动序列表学习资源` 的汇总基础

## 师生交互过程要求

### 字段类型（对齐 demo.json）
对应 demo.json 中的 `师生交互过程` 字段：
- 活动级（根层 `活动序列` 下）是**字符串类型**
- 任务级（`活动任务序列（任务）` 下）是**对象结构**
- 任务级 `value`: 数组类型（每一轮交互作为数组元素）
- 任务级 `images`: 空数组 `[]`

活动级示例：
```json
{
  "师生交互过程": "教师陈述、唤起先决知识：总结上次课内容并引出新课。"
}
```

任务级示例：
```json
{
  "key": "师生交互过程",
  "value": [
    "教师：...",
    "学生：...",
    "教师：..."
  ],
  "images": []
}
```

### 通用原则
1. 采用时间线式描述。
2. 每一轮互动都同时写教师行为和学生行为。
3. 体现具体教学策略，而不是空泛口号。
4. 写出关键引导语、追问语、总结语。
5. 教师行为要具体可操作，学生行为要具体可观察。
6. 尽量避免只有简单问答，要让学生发生比较、分类、归纳、演绎、应用等思考。
7. 目标是让同专业教师看到后可直接参考上课。
8. 必须与任务描述中的教学策略、教学方式保持一致。
9. 重点描述教学实施过程，不需要写成逐字稿或课堂剧本。
10. 建议形成”教师动作 → 学生反馈 → 教师回应 / 总结”的闭环。

### 任务内交互推荐格式

```text
1. 教师：利用具体资源或案例创设情境，并提出聚焦问题（采用××教学策略）
   学生：观察、回忆、回应或尝试操作
2. 教师：根据学生反馈追问、比较、示范或纠偏（运用××教学策略）
   学生：讨论、分析、练习、表达判断
3. 教师：顺着学生思路总结归纳 / 评价反馈 / 布置后续任务
   学生：记录、修正、提交结果或提出疑问
教学策略：××法、××法
```

### 课下任务特别要求
课下任务的交互重点不是全过程陪伴，而是**任务布置时的关键互动**。通常应包含：
- 任务要求说明
- 资源提供
- 疑问解答
- 时间要求
- 提交方式

写法要求：
- 以学生执行行为为主，教师部署与指导为辅
- 教学策略应包含 `自主学习法`
- 可补充 1-2 种策略：项目驱动法、任务驱动法、实践练习法、探究式学习法、翻转课堂法

### 常见教学策略
#### 帮助理解
- 案例分析法
- 对比分析法
- 引导发现法
- 归纳总结法
- 情境创设法
- 问题引导法
- 经验连接法
- 示范法
- 分层练习法
- 个别辅导法

#### 帮助记忆
- 顺口溜法
- 关联记忆法
- 重复记忆法
- 图表记忆法

#### 帮助运用
- 实践练习法
- 任务驱动法
- 项目教学法
- 反思总结法
- 人机协同法
- 探究式学习法
- 翻转课堂法

## 学习成果及评价标准

### 字段类型（对齐 demo.json）
对应 demo.json 中每个任务的 `学习成果及评价标准` 字段：
- 是**对象结构**
- `key`: "学习成果及评价标准"
- `value`: 数组类型（"学习成果："和"评价标准："开头的条目）
- `images`: 空数组 `[]`

```json
{
  "key": "学习成果及评价标准",
  "value": [
    "学习成果：1. xxx；2. xxx",
    "评价标准：1. xxx；2. xxx"
  ],
  "images": []
}
```

规则：
- 每个任务都要有明确学习成果，且学习成果必须有
- 学习成果必须与知识目标、能力目标、任务描述中的学习目标对应
- 学习成果必须可呈现、可测评，不要写成无法验证的笼统表述
- 评价标准要具体、客观、可操作，并直接指向学习成果
- 建议 `学习成果及评价标准.value` 使用数组结构
- 尽量允许学生修改并再次提交
- 评价标准最好提前告知学生
- 可根据任务目标设置分值、归属成绩类别与总评占比

常见学习成果形式包括：
- 文本、报告、课堂作业、课堂笔记
- PPT、视频、音频
- 实物模型、产品
- 学生行为表现

认知层级与评价方式建议：
- 记忆：更适合小测验、客观题等形式
- 理解：更适合阐述、分类、PPT 展示、口头说明等表征式成果
- 运用：更适合操作、产品、设计、任务成果等应用型成果

### 记忆类知识点
若任务包含记忆层次内容，学习成果宜设计为：
- 选择题
- 填空题
- 判断题
- 简答题

评价原则：
- 答对得分
- 答错得 0 分
- 明确标注正确答案和分值
- 必要时可补充行为量表、产品评价或阐述说明形成综合评价

## 备注

可包含：
- 教学心得
- 教学反思
- 学情信息
- 学生常见问题
- 需要重点关注的学生特征
- 学生有效学习方法
- 学生反馈与建议
- 教学活动反馈、教学目标达成度、素质目标体现情况

要求：
- 具体
- 有诊断价值
- 能指导后续教学改进
- 建议体现“学习状态 → 教学手段 → 认知转化 → 技能 / 思维内化”的逻辑链
- 尽量包含具体知识点、具体方法与具体达成效果，避免空泛表述

## 输出前检查

生成最终结果前，逐项检查：
- `标题`、`课程设计名称`、`课程设计`、`活动序列` 四个根层字段完整
- `课程设计` 数组中的 8 个板块完整且顺序正确
- `课程设计` 中的 `活动序列.value` 与根层 `活动序列` 活动名称一致
- `sorted_names` 与实际活动键一致，且无多余换行或空格
- 学习目标、活动目标、任务设计、资源、评价标准前后对应
- 活动目标与知识建模图一致，且已排除绿色先决知识
- 课上 / 课下时间与活动明细总和一致
- 课上与课下时间分配已基于活动与任务时间正确汇总生成
- 第一个活动已有导入任务，其他活动无导入时使用 `/`
- 每个活动都有活动目标
- 若某活动包含多个活动目标，`课程设计[].活动序列.value.活动X` 中已拆成多条独立记录，而不是只保留一个总目标
- 根层 `活动序列.活动X.活动目标` 已完整汇总该活动下全部活动目标，无遗漏
- 每个活动都有导入任务描述或合理占位
- 每个活动都有任务数组
- 每个任务都有语义清晰的任务名称
- 每个任务都有教学方式字段结构
- 每个任务都有师生交互过程
- 每个任务都有学习成果及评价标准
- 每个任务都有备注
- 教学资源、课上资源、课下资源已经从子项资源 / 任务资源完成汇总、分类、去重并完成教材页码合并
- 活动序列表中的 `活动目标`、`地点`、`时间`、`学习资源` 已基于活动与任务内容正确汇总生成
- 第二类课程包含 `能力目标`
- JSON 可正常解析
- 字段名称、嵌套层级、数组结构尽量对齐 `references/demo.json`

## 最终输出方式

### 若信息不足
先简短追问缺失的必填信息，不急着输出半成品 JSON。

### 若信息已足够
直接输出最终 JSON，不额外附加长篇说明。

### 禁止事项
- 不要只输出大纲
- 不要只输出 Markdown 教案
- 不要省略根层 `活动序列`
- 不要把任务写成纯段落导致字段结构丢失
- 不要随意修改固定中文字段名
- 不要让 `checkbox` 结构失效
- 不要生成与 `references/demo.json` 明显不一致的层级
