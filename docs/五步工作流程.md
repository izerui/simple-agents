## 详细流程说明

### 步骤 1：[规划] (Plan)

**目标**：深入理解用户需求，制定详细的研究计划

**核心操作**：
1. 使用 `create_directories()` 创建目录结构
2. 使用 `write_file()` 在 `.cursor/plans/research_plan.md` 中创建研究计划
3. 使用 `update_research_plan()` 更新计划

**计划内容**：
- **成功指标**：明确完成标准
- **检索路径**：计划文件读取顺序
- **任务分解**：将复杂问题拆解为原子任务
- **关键问题**：列出需要回答的具体问题

**输出产物**：
```
.cursor/plans/research_plan.md
```

**示例计划**：
```markdown
# 研究计划

## 成功指标
- 找到所有相关文件
- 提取关键统计数据
- 生成对比分析

## 检索路径
1. 先读取文件 A
2. 再读取文件 B
3. 最后读取文件 C

## 任务分解
- [ ] 任务 1: 读取并总结文件 A
- [ ] 任务 2: 提取文件 B 中的数据
- [ ] 任务 3: 对比文件 A 和 C

## 关键问题
- 问题 1: X 是什么？
- 问题 2: Y 如何影响 Z？
```

---

### 步骤 2：[感知] (Survey)

**目标**：识别所有潜在的信息源，过滤无关内容

**核心操作**：
1. 使用 `glob()` 或 `ls()` 查找文件
2. 使用 `grep()` 搜索关键词
3. 使用 `read_file()` 快速扫描
4. 使用 `update_research_plan()` 更新相关文件列表

**关键原则**：
- **先识别后深入**：先找所有可能相关的文件
- **快速过滤**：通过摘要快速判断相关性
- **避免盲目搜索**：有目的地搜索

**输出产物**：
- 更新后的 `.cursor/plans/research_plan.md`（包含文件列表）

**示例更新**：
```markdown
## [Survey] 更新 - 2024-01-15 10:30:00

### 发现的相关文件
1. file_a.md - 包含 X 的定义
2. file_b.txt - 包含统计数据
3. file_c.md - 包含相关案例

### 过滤掉的文件
- unrelated_file.md - 内容与主题无关
- draft_v1.txt - 过期草稿
```

---

### 步骤 3：[执行] (Execute)

**目标**：委托子代理执行原子化的研究任务

**核心操作**：
1. 使用 `task()` 工具委托子代理
2. 每个子代理专注一个原子任务
3. 使用 `save_temp_note()` 保存中间结果
4. 使用 `update_research_plan()` 标记进度
5. 使用 `think_tool()` 反思和规划

**原子化任务类型**：

**提取型任务**（最常用）：
```
"读取并总结文件 X 中关于主题 Y 的内容"
"提取文件 X 中的所有数据点"
"列出文件 X 的主要论点"
```

**对比型任务**：
```
"对比文件 A 和文件 B 中关于 X 的观点"
"分析文件 A 和文件 C 中数据的差异"
```

**输出产物**：
```
.cursor/temp_notes/
├── task_1_summary.md
├── task_2_summary.md
├── task_3_data_extraction.md
└── ...
```

**中间结果示例**：
```markdown
# Task 1: 读取文件 A

## 关键发现
- 发现 X 的定义
- 找到 3 个重要观点

## 数据提取
- 数据点 1: ...
- 数据点 2: ...

## 引用来源
- [1] file_a.md
```

---

### 步骤 4：[综合] (Synthesize)

**目标**：整合所有发现，生成最终报告

**核心操作**：
1. 读取 `.cursor/temp_notes/` 中的所有中间结果
2. 审查所有子代理的发现
3. 整合信息，构建逻辑结构
4. **严格执行段落编号引用**
5. 使用 `write_file()` 生成 `/final_report.md`

**引用规则**：
- 每个段落必须引用来源
- 使用 `[1]`、`[2]`、`[3]` 格式
- 为每个文件或子代理发现分配唯一编号
- 按顺序编号，不跳号

**报告结构**：

**比较类报告**：
```markdown
# 引言
## 主题 A 概述
## 主题 B 概述
## 详细比较
## 结论

### Sources
[1] 文件名：具体路径/文件名.md
[2] 子代理发现：任务描述
```

**摘要类报告**：
```markdown
# 主题概述
## 关键概念 1
## 关键概念 2
## 关键概念 3
## 结论

### Sources
[1] 文件名：具体路径/文件名.md
[2] 文件名：另一个文件.txt
```

**输出产物**：
```
/final_report.md
```

---

### 步骤 5：[验证] (Verify)

**目标**：检查报告质量，确保满足原始需求

**核心操作**：
1. 使用 `verify_report()` 工具
2. 对比原始请求和最终报告
3. 检查引用链条完整性
4. 检查逻辑一致性
5. 如发现问题，回到相应步骤修正

**验证检查项**：
- ✅ 报告是否完整回答了用户问题？
- ✅ 每个观点是否有对应的引用？
- ✅ 引用编号是否连续且正确？
- ✅ 来源是否真实存在？
- ✅ 结论是否基于证据？
- ✅ 是否有自相矛盾的地方？

**验证报告示例**：
```markdown
## 验证报告

### ✅ 通过的检查
- 找到 5 个唯一引用
- 报告包含 6 个章节
- 关键词覆盖率: 85.0%

### ❌ 发现的问题
- 引用编号不连续: [1, 2, 4, 5] (缺少 [3])
- 报告可能未充分覆盖原始请求的关键词 (覆盖率: 85.0%)

### 建议
- 发现 2 个问题，建议进行修正。
```

## 常见问题

### Q: 为什么会达到递归限制？

**A**: 五步流程涉及多次工具调用和子代理委托，容易超过默认的 25 次限制。解决方案：
- 将 `recursion_limit` 设置为 500 或更高
- 已在 `subagents.py` 中为所有子代理设置 recursion_limit: 500

### Q: 什么时候应该使用多个子代理？

**A**: 仅在以下情况使用并行子代理：
- 明确需要比较不同事物
- 主题有明显独立的方面
- 主题地理分离

### Q: 如何避免过度搜索？

**A**: 
- 明确每个任务的停止条件
- 使用 think_tool 反思是否有足够信息
- 遵循"先识别后深入"原则

### Q: 引用格式有严格要求吗？

**A**: 是的！每个段落必须引用，使用 `[1]`、`[2]` 格式，并在报告末尾列出所有来源。
